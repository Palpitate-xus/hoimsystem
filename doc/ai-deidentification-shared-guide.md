# 病例去标识辅助：共享任务接入

本阶段将第 75 项接入共享任务目录、队列和 worker。它只对已明确授权的单个患者、明确项目中选定的完整文字字段提出部分逐字候选。候选没有经过人工审核，不代表完整识别或已经匿名，也不会自动遮蔽正文、建立人工复核、发布导出或下载文件。

## 明确来源与用途

项目候选目录只提供项目技术引用。目录中出现某个项目、医生当前 care 权限或超级管理员身份，都不授予研究目的权限。读取临床来源、预览、模型调用、结果接收及分件读取，均重新核对项目当前用途、Project ACL 和该患者的明确授权；模型出站与本地核查分别授权。已有 74 项科研队列的授权不能自动替代 `deidentification_review`。

从实际患者业务行进入时，患者和项目必须与选择的 Case 一致。已有 `deidentification_case_id` 可以在普通当前读取成功后用于反查范围；失效任务的技术元数据不能用于自动恢复患者或项目正文。没有真实授权范围或 Case 时，入口应明确不可选择，不能猜测 UUID 或使用全院患者目录。

新任务只提交 `deidentification_case_id` 和可选的原样问题。问题最多 2000 个 Unicode 码点、8000 个 UTF8 字节。问题不是来源证据，也不能扩展所选患者、字段、项目用途或导出权限。

## 任务与完整分件

共享创建返回短任务元数据，客户端按同一任务 ID 读取当前详情。完整来源、私有范围、冻结任务和结果通过四个独立分件读取；每件为原始 canonical JSON HTTP 正文，各自最多 8MiB，没有额外 `code/data` 包装，也不承诺合并后仍小于 8MiB。

- `source`：模型所见的完整公开来源；包含所选文字，因此仍属于受控临床信息。
- `scope`：完整私有 Case 快照、原件与授权绑定。
- `task`：实际固定 System、版本化 Task、Provider、执行快照、原始三项任务 JSON 字符串与对应 SHA。
- `result`：服务器根据模型草稿和原来源核对后保存的完整结果；无已接收结果时为 JSON `null`。

原文 BOM、CRLF、emoji、空串和 NULL 均原样保留。引文使用 Unicode 码点半开区间 `[start,end)`，不得按 UTF16 索引或规范化后的文本解释。浏览器核对实际分件原 UTF8 SHA，使用唯一来源投影核验所选完整字段；Provider 的 `1.0` 等数值原字面量和三项原始任务 JSON 不得经 `parse/stringify` 后冒称原字节。

读取任何临床分件前都必须通过当前用途授权。超级管理员在授权撤回后，也只能查看技术状态、独立实际用量及不透明 SHA，不能通过 Trace、原始任务字符串或冻结来源恢复临床正文。技术目录中缺少永久 Artifact 的原型旧行没有可用来源，不会退回通用模型或通用摘要。

## 用量、取消与恢复

排队和执行中的未知用量保留 NULL。只有具体、可核对的未调用证据才记录输入和输出均为零；实际模型回执的两项用量可以独立为 NULL。取消在途任务不撤销已发生的模型费用，也不会把未知用量补零。

普通用户取消任务仍需当前用途权限。当前超级管理员可以在来源失效后通过仅技术路径停止接收排队或在途任务；这项管理操作不恢复来源读取或新执行资格。在途取消后，原 worker 仍提交真实付费回执，但不接受候选结果。

每个专用 claim 使用具体 Audit 主键；dispatch 持久回执提交后才允许发起模型请求，等待 HTTP 时不持有 SQL 事务。错误、缺失、布尔或重复的 claim 主键不会触发第二次付费调用。中断恢复保留未知状态，不自动重放可能已经付费的请求。队列按永久 Artifact 域分派，损坏的研究任务不会降级为通用任务，也不能永久阻塞后方有效任务。

## 本阶段验证边界

本目录对应专用、合成工程验证：memory SQLite / 实际 Main JWT ASGI / Chat 与 Responses MockTransport，以及独立、无网络的私有 MySQL 容器。它们不代表医院真实资料、远程模型质量、匿名安全认证或伦理批准。后端定向模块回归、私有 MySQL、前端守卫及未来生产构建的结果分别记录，不累加为一次全量通过。
