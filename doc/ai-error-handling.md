# 模型报错与恢复

任务详情展示失败原因、处理建议及技术信息。超级管理员在“任务与反馈”按任务编号查询状态、原模型配置和用量，在“模型服务”修改服务配置。

| 情况 | 系统处理 | 处理办法 |
| --- | --- | --- |
| HTTP 401 | 单次结束，显示认证失败 | 管理员更新密钥和凭据配置 |
| HTTP 403 | 单次结束，显示模型访问受限 | 管理员检查账号模型权限、服务访问策略 |
| HTTP 404 或重定向 | 单次结束 | 核对模型名称及可直接访问的接口地址 |
| HTTP 400、413、422 | 单次结束 | 检查输入范围、模型参数和请求格式 |
| HTTP 402 | 单次结束 | 检查服务余额、账单和配额 |
| HTTP 429、502、503、504 | 按配置有限重试 | 重试后仍失败可稍后重新生成；限流时检查并发和配额 |
| HTTP 500 等其他失败状态 | 单次结束 | 管理员检查模型服务及对应请求日志 |
| 建立连接失败 | 按配置有限重试 | 检查服务进程、网络和地址 |
| 发送、读取或关闭连接中断 | 结束本次调用 | 先核查任务记录和模型服务执行情况，再决定是否重新生成 |
| 超过总时限 | 停止后续尝试 | 核查模型负载、任务记录及服务端执行情况 |
| 格式错误、未完成、拒绝回答、引用不匹配 | 拒收本次结果 | 按具体原因核对结构化输出支持、输出上限、Prompt、知识来源或模型策略 |
| 执行期间权限、配置或租约改变 | 停止后续调用或接收结果 | 刷新任务，核对当前授权和配置 |

## 重试设置

文本模型服务的“最多尝试次数（含首次）”为 1–3。1 表示单次调用；新服务默认 3，旧服务保留原配置。重试使用指数退避和随机间隔，单次等待最多 2 秒。有效 `Retry-After` 超过等待上限或剩余总时限时结束本次调用，按服务要求等待后再处理。

所有尝试、退避、响应读取和连接关闭共享配置的总时限。只有可重放的 JSON 文本请求参与重试；录音、影像、心电等上传按各自专用协议执行。每次重发前重新核对原任务租约、取消状态、权限、模型、功能、Prompt 和来源授权。

## 页面查询恢复

工作台状态查询失败后显示“状态查询暂停”，保留原任务编号和真实状态。点击恢复查询只读取原任务。已收到创建回执但详情查询失败时，继续查这项任务。

创建回执丢失时，页面提示先检查任务记录，并暂停相同内容的再次提交，减少重复创建。浏览器的查询失败与后台任务执行状态分别显示。

教学和运维页面显示中文任务状态；失败时展示原因，并可展开错误码、HTTP 状态和尝试次数。业务接口的登录失效与权限不足按应用自身状态处理。

## 用量、保存失败与 worker 中断

缺失的 token 数保存为未知，部分已知数分别保留，服务明确返回的 0 保持为 0。先前 HTTP 尝试可能产生用量而没有完整回执时，总量保持未知。

普通任务保存结果失败后，先回滚该事务，再以原任务编号和租约通过独立事务记为 `RESULT_STORAGE_ERROR`，保存实际用量及失败审计。已取消任务保留取消状态。恢复流程不重新请求模型。

worker 长时间中断后，原任务按过期租约结算；已领取但没有用量回执的默认零改为未知。原生专用任务继续按各自独立用量协议恢复。持久化仍不可用时，由后续过期恢复处理。

日志记录任务编号、功能、阶段、错误类型和重试技术信息。Prompt、患者正文、服务响应、密钥及 SQL 参数不写入故障日志。连续 worker 故障按 1、2、4、8 秒递增退避，最多 60 秒，成功轮询后恢复正常间隔。`python -m app.ai.worker --once` 基础设施执行失败时返回退出码 1。

测试与本地模拟验收结果见[报错与恢复验证](validation/2026-10-29-llm-errors.md)。
