# AI 平台开发与使用指南

## 当前交付边界

AI 平台提供 80 项候选能力的独立任务 Prompt、共享文本模型网关、专用模型接口契约、超级管理员管理台、权限范围内的患者资料、审核知识检索、持久化任务、引用展示和人工反馈。

文本能力可通过共享业务工作台调用。每个功能是否适合实际业务，仍取决于其模型配置、输入数据、已发布知识及验证状态。语音、影像、心电、预测和优化按各自专用适配器或受审本地固定计算执行，缺少对应来源、配置或验证时返回未就绪原因。第78项只运行本地固定统计，不配置外部模型。功能出现在目录中不表示已经完成专病或专用模型验证。

项目不自动创建外部模型账号，不预置真实临床知识或虚构模型回答。现有处方、医嘱、签名、收费和预约流程继续承担业务执行与权限校验。

全部80项工程接入的历史验证见[最终工程验证记录](ai-final-integration-verification.json)。2026-10-26的默认Prompt、文书复核及界面优化另见[本轮体验验证记录](ai-experience-verification.json)，按本轮实际测试范围记录，不沿用历史全量通过数。工程验收不表示模型或临床效果已验证。

管理台按“功能与模型、知识与数据、任务与用量、权限与审计”四组展示原有41个入口。“查找管理入口”可直接搜索所有有权访问的页面，原名称仍可查找；从任务或来源跳转时，分组随当前页面切换。

## 本地启动

在 `fastapi_be` 中配置现有数据库及 JWT 环境后，先执行数据库迁移，再分别启动 API 和 worker：

```bash
python -m app.db_migrate
python -m uvicorn app.main:app --reload --port 8000
```

另一个终端使用相同环境启动：

```bash
python -m app.ai.worker
```

`python -m app.ai.worker --once` 最多处理一项任务，适合诊断；常驻 worker 默认每两秒轮询。已有未纳入 Alembic 管理的数据库按原部署手册核对、备份并接管，不直接跳过迁移检查。

前端在 `vue3-new-ui` 中运行 `npm run serve:rspack`。业务入口为 `/#/ai/workbench`，超级管理员管理入口为 `/#/ai/manage`。Docker Compose 已增加 `ai-worker`，并等待数据库迁移完成后启动。

## 超级管理员配置顺序

1. 部署环境将实际模型主机加入 `AI_PROVIDER_ALLOWED_HOSTS`。默认仅允许本机，远端端点使用 HTTPS；重定向不会被跟随。
2. 选择密钥方式：配置 `AI_MODEL_API_KEY`，或配置至少 32 字符的稳定 `AI_CREDENTIAL_KEY` 后在管理台加密保存 API 密钥。模型配置查询和配置审计不回显明文或密文密钥。
3. 在“模型服务”中新建文本服务或专用适配器。文本服务类型支持 Chat Completions 兼容协议与 Responses API；模型标识填写服务实际提供的名称。
4. 若服务获准处理患者和临床资料，显式开启该服务的患者资料权限。缩减直接标识不等于完全匿名化。
5. 在“知识审核”中创建有来源、版本、适用功能和有效期的知识草稿；核对全文后发布。只有已发布且仍有效的适用知识参与检索。
6. 在功能配置中选择模型、授权角色及每日调用上限。临床能力完成验证并登记依据后才能面向业务启用；超级管理员可使用明确标记的评估预览。
7. 根据实际诊疗关系使用患者资料。需要额外访问时，在“患者访问授权”中登记用途、范围和到期时间，授权最长 90 天。

文本服务还可配置“最多尝试次数（含首次）”：1 关闭自动重试，2 或 3 限定总尝试次数。新建文本服务默认 3，升级前已有服务保留单次策略；专用适配器保持单次，不重放录音、影像或波形上传。每次任务冻结当时的重试设置，管理员变更配置按原 revision/CAS 规则生效。

临时 429/502/503/504 或连接建立失败可有限重试；所有尝试和等待共用原超时预算。有效 Retry-After 要求超出本次等待上限或剩余时限时停止，不能提前重发。鉴权、配置、结构、引用错误以及已开始交付的回复不自动重发。重发前复核任务状态、租约、当前服务/功能/Prompt、发起人权限及来源授权。前次 HTTP 失败无法证明用量时，整体用量保留未知，不使用最后一次 token 数冒充总量。

退避采用随机间隔，响应读取与连接关闭也计入原时限。任务报错会给出对应处理建议，并保留 HTTP 状态、已尝试次数和安全审计。浏览器查询中断可恢复查询原任务；提交回执不确定时先查看任务记录。具体规则和排查入口见[模型报错与恢复](ai-error-handling.md)。

不配置真实模型时，可按[本地模拟服务说明](../fastapi_benchmark/llm_simulator.md)使用带明确模拟标记的合成回复，验证接口、任务和重试流程。模拟通过不等于真实推理通过；本轮各层结果见[系统验证记录](validation/2026-10-27/README.md)。

院内临床路径通过“知识审核 → 从临床路径导入”另建待审核快照。导入保留当前模板的原始字段、版本、完整步骤及适用/排除条件；步骤必须是非空JSON数组或含`steps`数组的对象，重复字段、无效数值及过大/过深结构不自动解释。原JSON文本保留，解码展示中的数字按文本保留精度。选择适用AI功能、科室及有效期后保存，再核对全文并单独审核发布；模板的启用状态不表示完成审核。

快照绑定原路径、递增来源版本和内容哈希。原模板修改、停用或删除后，旧快照不再被检索，也不计为可用审核知识；停用后恢复相同原文仍需重新导入审核。已停用的路径知识版本不能直接重新发布。独立知识表单不能手工伪造院内路径来源地址。以上操作仅限超级管理员，不调用模型，也不改写原路径和患者入径状态。

“能力与启用”中的配置检查会逐项列出模型、凭据、用途权限、适配器声明、审核知识和临床验证缺口。检查只核对基础依赖；真正执行时仍按科室、患者、问题和时间筛选知识及资料。模型服务显示“已启用”仅表示配置开关，不表示完成真实联通或临床效果验证。

“任务与反馈”支持按能力、状态、发起用户、患者及包含的反馈类型分页查询全院任务。超级管理员可查看每次调用的原始 Prompt、请求模型、输出上限、验证记录、输入资料、工具结果、依据及历次反馈，也可取消接收正在排队或生成的结果。模型和 Prompt 的后续修改不会覆盖旧任务已经留存的快照。旧任务未保存的字段按缺失展示。

“反馈脱敏审核”提供评价目录、脱敏稿及版本审核。目录只给出原评价时间、评分和科室等元数据；读取原评论另记审计。按评价标识查询时可跨日期查找，未指定标识时默认近30天。先核对自动缩减直接标识的建议，补查第三方和间接识别线索后保存待审核版本；保存草稿不会调用模型或发布文本。审核页面须重新读取原评价，对照原意和身份线索，明确勾选两项确认并填写说明才能发布。自动建议和人工审核均不构成匿名化保证，也不证明反馈事实或责任已调查属实。

每次发布前核对原评价内容、评分、时间、患者/医生/就诊关联、有效科室及已知标识资料。修改文本必须另存新版本，发布新版本自动停用同一原评价旧的发布版本。原文、关联或版本文本校验变化时，旧稿不进入后续模型资料；来源无法核实的已发布版本仍可停用。任务调用前后重新校验，停用后排队任务不再发起调用，生成中的结果会被作废。普通使用者对包含失效片段的旧任务失去访问权，超级管理员仍可在冻结审计中追查当时使用的版本。

普通管理员与业务角色不能管理上述 AI 配置。功能使用角色受固定业务边界与管理员配置共同约束；超级管理员的管理权不会通过普通管理员的 `admin` 权限继承。

收费员可被配置使用“收费与漏记账核对”，须由超级管理员授予“运营与收费”范围的限时患者访问。新任务从实际住院收费记录进入，明确患者、同次住院和受审完整账目原件；不加载患者其他病史。旧版账单任务仍保留授权历史读取，不能作为新版完整账目任务提交。已有功能配置的角色列表不会自动扩展，需在管理台明确选择。

药师可被配置使用药品耗材需求预测及库存分析，其医院级读取仅限明确品种的库存资料，不获得全院经营或财务数据权限。科室主任使用所属科室原始记录汇总；库存尚未按科室保存归属时不向科室范围提供全院库存。业务角色及配置仍共同限制实际可用功能，旧配置不会自动新增药师授权。

## Prompt 生命周期

- 默认 Prompt 位于 `app/ai/catalog.py`，每个功能都有独立任务目标、需核查输入及具体产出要求。
- 固定系统契约每次调用始终附加，规定事实边界、来源、缺失信息、数据用途和禁止自动执行业务操作。
- 管理台修改任务 Prompt 时创建新的不可变版本；可以激活历史版本或回到默认 v0。
- 更换活动 Prompt 或模型会关闭关联能力，等待重新验证启用。旧任务保留其原版本与资料摘要。
- 请求输入与检索文档放在数据消息中，不能覆盖系统指令。模型不能指定 SQL、执行系统命令、访问任意 URL 或直接修改业务数据。

`2026.10.26.1` 默认目录更新了任务表达要求：医生、护士、患者、管理人员和学员分别使用适合当前工作的措辞；直接呈现具体事实、依据、缺口和待办，减少寒暄、空泛结论及反复出现的通用声明。逐字引文、数字、否定、单位和适用条件继续保留原文。固定系统契约、专用JSON结构、服务器固定结果文本和本地统计配方保持原有契约。

目录升级不会覆盖已保存或当前激活的自定义Prompt，也不会自动关闭、重置或重新验证已有功能配置。超级管理员应在“能力与启用”中查看实际活动版本，按需比较默认任务文本、另存新版本并完成验证。仍使用默认v0的功能在后续新任务中读取新默认文本；旧任务继续展示冻结版本，旧排队或生成任务按原有目录版本检查处理。

## 工作台与文书复核

医生病历、处方、住院病历、手术、病案首页及发药行使用“检查病历、核查处方、术前评估、核对病案首页、核查用药”等业务入口。输入仍绑定原业务对象；进入页面不会代替使用者提交任务。

结果主区域展示实际发现、依据、资料缺口和人工复核事项。模型与Prompt配置、原始JSON及技术核验过程按需展开，必要的任务状态与实际用量仍就近展示。未知数值显示为未知，实际零值保持零；专属任务可用时不再同时显示“暂无可用能力”。

门诊病历、入院记录、病程、出院小结和影像报告草稿的“文书正文”与生成摘要、警示及缺失资料分开。“复制文书正文”会打开栏目核对框；选择要复制的栏目，存在警示或缺项时须确认已核对，改选栏目会清除该确认。剪贴板只包含所选栏目标题及正文，保留原字符和栏目顺序；摘要、警示、资料缺口及来源链接不混入正文。没有正文栏目时不能把摘要复制成文书。身份、患者、来源或任务变化会清除旧复制范围。

教学页面在当前授权允许时自动检查AI讲解配置；点击“选择课程”读取课程目录。先选课程、作答并确认提交，查看固定成绩和课程解析；随后选择讲解目标，点击“获取AI讲解”创建独立任务，也可从本人已提交记录进入。参考材料随受审课程及本人提交绑定。任务完成后自动核对并展示反馈，固定成绩与模型反馈分开。来源或权限变化时继续执行原有清理和拒收检查。

## 任务与证据

提交任务后，服务器先检查角色、患者关系、模型用途和所需知识，冻结资料、Prompt 和证据版本，再由独立 worker 处理。当前知识检索使用有版本的段落关键词检索，检索不到适用知识时明确拒绝相关任务。

患者摘要区分当前就诊与既往、已签名与草稿、已审核与未审核、处方记录与实际服药。治疗路径推荐要求指定本次就诊，并取得责任医生单独复核为“已明确”的诊断；单纯病历签名不会产生确诊状态。

明确选择院内路径或原入径记录时，治疗推荐还要求该路径当前来源匹配、适用于本功能和科室、且已审核发布的知识版本。其他通用资料不能替代所选路径的审核；所选路径知识优先纳入检索，结果有分节时必须包含该路径审核版本的引用，否则拒收。来源标识校验不等同于证明模型陈述与原文语义一致，仍须人工逐项核对纳入、排除条件及建议依据。

病历与报告行传入的明确资料标识会校验患者归属，并优先纳入有限快照。快照显示截断范围，不能据有限近期记录断言不存在其他病史或用药。患者端不加载未签署病历、未审核报告及医护住院工作笔记。

资料预览与提交使用相同的服务器来源解析。病案首页、手术申请、排台、围术期用药和门诊/住院费用等来源通过 `POST /api/ai/context` 的 `source_refs` 传入；原有 `GET /api/ai/context` 保留五类既有来源参数。前端从能力元数据读取支持的引用键，服务端核对真实患者、父记录及就诊关系。

最近任务按所选功能、患者和本次就诊筛选。改变患者、处方或服务选项后，旧资料预览、提交回执与任务刷新不能覆盖当前界面；已经保存的任务仍保留原始范围和权限。

医院级资料使用 `POST /api/ai/operational-context` 预览，输入和提交共用日期、科室、品种及计划区间筛选。预览不创建推理任务，也不连接模型；能力未启用时，当前角色仍可核查其有权读取的原始资料。运营报表、病区床位和药品库存预警页面均有入口，工作台也支持直接选择范围。

模型返回必须满足 JSON 结构。引用 ID 必须来自本次服务器提供的来源；需要医学知识的回答必须引用已审核知识。ID 校验只证明引用属于已提供的材料，语义支持程度仍需人工核对。

worker 在执行前和保存结果前重新检查权限、配置、患者资料、确定性工具结果与知识有效性。患者资料、诊断确认、审方规则或目录改变时拒收旧结果；授权撤销、版本改变或知识停用后，旧任务不会静默使用新配置继续完成。`AI_MAX_QUEUE_AGE_SECONDS` 默认 900 秒，过期排队任务不发起模型调用。长时间中断的任务标记失败，避免自动重复可能计费的推理请求。

医院级任务同样重新读取日统计、原始汇总、床位、排班或所选库存；变化后拒收旧结果。历史任务读取还重新核对原科室或全院范围，调离科室或失去全院权限不会保留旧结果的访问权。运营引用包含范围、日期及读取时刻，当前界面展示的是任务冻结版本。

任务额外冻结当时的系统 Prompt、目录版本、请求模型配置、有效输出上限和人工验证记录。worker 输出限制与排队时不一致时拒绝调用。取消接收不会撤回已经发出的模型请求；若服务返回 Token 用量，取消任务仍保留该用量。全局统计只对具体独立回执核验已知计数，缺少或损坏回执及通用旧整数保留未知；输入和输出分别统计，未知不当作零费用。

结果使用纯文本呈现，附来源查看入口、缺失信息和人工反馈。采纳反馈用于审计与质量分析，不代表临床结论已验证；也不会自动写入病历或处方。

手术、首页/ICD、门诊与住院费用、院内导航、预约页面均有对应 AI 入口。编码、收费、路线和号源的原始工具结果附引用查看入口；模型解释不会覆盖这些原始结果。编码绑定、分组、收退款及预约仍通过原业务流程操作。

运营历史默认近 30 天，可选不含未来且最多 367 天的正序区间。医院数据问答的区间若完全早于当前业务日，不加载当前病区或床位快照，也不因无关的当前床位变化使历史分析失效；床位需求预测则单独保留当前容量供核查。排班/手术排台计划与历史资料分开，默认计划为业务日起 14 天，单次最多 31 天且不晚于业务日后 366 天。大范围资料可能超过模型输入预算，需缩小日期、科室或品种；原始清单若截断会明确标记。

手术页的“AI 排台分析”、运营页的评价分析，以及已关联患者的不良事件行“AI 事件复盘”，都能先查看资料再提交。事件行入口固定患者和事件，不展示就诊归属选择，结果同时展示冻结的原上报和原分析，并可检查引用。未绑定患者的组织事件仍待独立访问范围及数据连接，不强行归属某位患者。手术排台和反馈分析均受模型服务患者数据用途开关控制。这些入口接入批次的目录及Prompt版本为 `2026.10.20`，后续版本见下文；旧队列不会沿用更新前的固定任务契约。

临床路径模板页提供“AI 治疗方案比选”，固定所选路径后选择已授权患者和本次就诊。工作台也可选择当前科室及功能已有审核版本的路径；选择就诊后重新核对审核范围。路径执行行的“AI 路径复评”固定患者、所记住院、原入径和路径标识，补充JSON不能替换这些绑定引用。预览与生成使用相同标识，原模板元数据、原入径与变异、未知计数及引用独立展示，结果保存任务当时版本。新增、入径、变异、退出及用药仍走原人工业务流程。

生成前后重新核对路径知识、模板来源版本、入径计数及患者资料。排队期间变化不会发起模型调用，在途变化会拒收结果；模型已报告的Token用量仍保留。原入径没有在任务请求中指定本次就诊时，读取历史结果仍重新校验其中明确关联住院的访问权。原表没有冻结入径当时的模板或逐项执行，后续仍需补齐实际治疗时间线和效果评价资料。

转诊、MDT和ADR行提供绑定原患者与记录的AI入口；补充JSON不能替换行中绑定的这三类资料引用。预览和生成使用同一组标识，模型结果之外独立展示原记录及依据。转诊前端入口已对齐原临床接口，医生和科主任可访问；患者账号不加载内部转诊工作列表。所选就诊可补充临床背景，不代表这些无就诊关联的记录属于该次就诊。历史资料超出条数限制时仍优先纳入明确所选记录，并展示截断。

ADR列表对管理员保留既有管理范围；药师只读现有处方业务范围内患者的记录，范围取处方原状态0/1/2，与既有药事AI诊疗关系校验一致。患者不再有该处方业务关系时，下一次读取即排除相应记录。AI用途授权不扩展这个业务列表范围，确认/处理/排除仍由原管理角色执行。历史状态2需在“核实历史结果”中明确选择并填写说明。处理只修改ADR记录，不自动新增或删除过敏资料。

药物过敏与不良反应分开记录的设计参考[NICE CG183建议1.2.5](https://www.nice.org.uk/guidance/CG183/chapter/recommendations)。这里用于资料分类，具体患者的过敏和因果判断仍需单独核实；该网页未自动导入或发布为院内诊疗知识。

## 住院生理观测与风险时间窗

护士工作站的“结构化观测”按明确患者和原住院登记点测量、分时尿量，并另行冻结观测窗。页面不预填正常值、清醒状态、吸氧否或当前观察时间。切换患者、住院、会话或角色后清除未保存输入，迟到回执不能归入另一患者。创建原资料不会创建AI任务，也不会授予作者新的照护权限；护士首次登记仍须已有该住院照护关系或超级管理员授予的有效住院用途访问。

点测量分别保存心率、脉搏、呼吸频率、收缩压/舒张压、体温、SpO₂、FiO₂、体重及氧流量。数量使用原始十进制字符串，最多16位整数和8位小数，保留明确0与小数尾零，不接受浮点数或科学计数文本。单位固定为`/min`、`mm[Hg]`、`Cel`、`%`、`kg`、`L/min`，不自动换算FiO₂比例、互换心率与脉搏或依据血压文本猜测分项。未选指标不入资料，明确未测、未知或测量失败另存缺失原因，不能同时保存数值与缺失原因；仅记录测量尝试的缺失原因也不表示取得测值。

吸氧情况须明确选择是、否或未知；氧疗装置保留原文字。意识使用原AVPU或ACVPU体系，未观察时保持空值，不能从旧护理编码或GCS补齐。记录这些字段不等于选择NEWS2血氧分表、计算NEWS2或验证风险模型。

尿量按原收集开始、结束和原mL量保存，单独声明完整/部分/未知收集、是否患者该区间总量及原收集方法。真实0、未知量和部分收集分别保留，重叠区间允许作为原事实登记；不依据点值推断小时尿量，不按窗口边界分摊、不求和或计算mL/kg/h。跨边界、重叠、未知量、部分收集或未确认患者总量的区间不能充当完整尿量覆盖。

观察和收集时间必须是包含秒及明确时区的ISO时间，最多6位小数；系统另记实际录入时刻，全部按UTC微秒保存。无时区旧体征、体温单和危重文本不按日期归入住院，也不自动转成这套观测来源。三类新来源使用不可变正文、原患者/住院、作者、版本与SHA-256；不提供原地编辑、删除或恢复，纠错应撤销后另建，撤销要求当前版本和原因并留审计。原始点测量/尿量撤销受原照护范围和作者或既有管理角色限制；AI观测窗撤销限有原范围的作者或超级管理员，普通管理员不因此获得全院AI管理权。

观测窗创建时明确`start_at < end_at <= as_of <= 当前时刻`，最多168小时，单窗最多1000条合计来源（包括已撤销成员）；超过数量或冻结正文预算时拒绝，不能悄悄截取。点测量选择观察时间位于闭区间`[start,end]`且系统录入不晚于`as_of`的原行；尿量选择与半开区间`[start,end)`相交且录入不晚于`as_of`的原区间。目录最多显示100项是查询展示限制，不代表测量完整或连续监护齐全。

冻结正文标记`current_snapshot_retrospective`：这是当前核对的回溯资料，不能声称恢复了过去数据库状态。晚于`as_of`才录入的记录不进入旧窗，也不因其存在而泄漏未来资料计数；原成员删改、转属、撤销或新增本应符合截止条件的成员会使当前核对失败。撤销后的来源仍可在冻结审计中看到原状态，不能作为有效测量。质量区独立展示同刻重复或冲突、未测与未记录项、相邻有值时点间隔和首尾缺口，以及尿量交叠连通组、排除原因及未覆盖区间；无冲突不证明正确，离散时点间隔不证明期间连续监护。

病情恶化、脓毒症和急性肾损伤三项风险入口（41–43）只接受明确的`observation_window_id`及可选问题，预览与提交使用同一引用，能力元数据仅声明这一个来源键；其他能力不声明支持观测窗。补充JSON不能添加或替换生命体征、时间窗、旧护理引用或检验。其上下文不混入患者级最新体征、当前诊断、未明确住院关联的检验或较晚资料；未接入检验不能表述为“危急值0条”。窗口只对备注、原氧疗装置、收集方法及撤销说明等自由文字缩减直接标识，保留严格数量、单位、时间、UUID及哈希原值；原始来源哈希和治理哈希仍校验完整原文，缩减不构成匿名化保证。

排队、调用前后及普通历史读取重新核对原住院权限、窗口和各成员。原资料变化后普通旧结果失效，超级管理员仍可查看冻结审计；超级管理员发起新任务也不能绕过来源核对。风险/挂号预测页面在会话或角色变化时同时清除选择、草稿、结果及旧目录，旧患者/就诊回执不能重新填回；固定患者的业务入口需关闭再重开以重新确认范围。管理台的“住院观测窗”支持全院元数据筛选、冻结资料和缺口审计及按版本撤销，读取、冻结或撤销均不调用模型、不自动启用功能或登记临床验证。

### 受控住院检验与v2观测窗

新建窗口默认使用`inpatient_window_v2`，加入经核实的检验来源子集；已有v1窗继续按原构建逻辑核对，不补入后来登记的检验、项目映射或新质量字段，历史哈希及普通用户的有效历史读取保持兼容。检验来源批次的41–43只接受`observation_window_id`，其独立Prompt明确区分来源治理、模型适用性和临床验证，不能以有检验值推定已具备风险预测能力。该批目录版本为`2026.10.20.4`，80项独立Prompt与26个引用键保持完整。

超级管理员在“AI管理→检验项目与来源”手工建立项目映射草稿：填写经核实的来源命名空间、编码体系/编码、原单位、方法、标本及数值/定性类型，再选择项目分类和填写审核依据。九个项目分类只是管理选项，没有预装已验证映射、参考范围、风险阈值或单位换算。发布须明确确认项目语义和原签名，一份精确身份在同一命名空间只允许一个已发布版本；撤销后才能另行审核替代版本。草稿、发布、撤销均保留不可变正文、内容摘要、治理摘要、版本和审计，不支持修改、恢复或删除。

匹配区分大小写和原单位符号，不从显示名猜项目，不把不同系统的`local`编码自动合并；缺方法、缺标本不作通配符。此身份结构参考[LOINC项目术语的主要组成](https://loinc.org/kb/users-guide/major-parts-of-a-loinc-term/)和[UCUM的单位语义](https://ucum.org/ucum)，但每份映射仍须院方实际核实，并未获得术语服务认证。

医生、主任、管理员和超级管理员可在现有住院照护权限内登记检验来源，护士不能新登记，护理界面只读。候选目录仅说明同一患者的已审核原结构化观察项，不证明属于当前住院，不自动选择最近报告；同范围护士可只读候选API，护理界面不加载登记候选。登记者须分别确认并填写至少20字依据：实际采样UTC、明确原住院关联、原来源命名空间。原数值、单位和身份从数据库读取且只读；请求同时携带原资料与映射摘要，资料变化须重新核对。原报告须已审核，已有审核者和录入者不得相同；LIS自动录入没有人工录入者时，单个人工审核不能称为双人复核。

原检验Decimal保存为数据库现存十进制文本，保留`0.00000000`、NULL和定性原文；这不证明最初输入的字面尾零或超出原库精度的原值。旧采样、报告和审核时钟保留原无时区值，不添加Z；固定六位小数序列化不提高原库或原采集精度。人工确认的`collected_at_utc`另行保存，`registered_at == available_at`为服务器本次核实后纳入AI的时刻，不可倒填，也不声称是原LIS首次发布时间。[FHIR Observation的effective与issued区分](https://hl7.org/fhir/R4/observation-definitions.html)及[DiagnosticReport的issued定义](https://hl7.org/fhir/R4/diagnosticreport-definitions.html#DiagnosticReport.issued)用于说明这一边界；人工依据仍是声明，不是独立时间证明。

一条原观察项同时只能有一个活动住院来源，跨住院、跨映射也不能重复登记；纠错先按原版本撤销，再核实另建。普通原作者撤销须仍有该住院当前照护读取权限，转为护士后也可经API撤销本人旧登记，护理界面不提供这个动作。超级管理员可按存储的原范围治理冻结来源，即使原住院已删除。来源哈希绑定原申请/报告/结构化观察项、原审核及临床正文，不把同步时间或危急值处理流程变动作成检验值变化。原内容、归属、审核或映射变化会阻止旧来源继续作为当前输入；普通用户读取失效来源不显示旧冻结正文，超级管理员仍能追查冻结审计和按版本撤销。

v2只选采样UTC位于`[start,end]`、登记及本次可用时间均不晚于`as_of`的受控来源；不查询未登记检验或报告“未来来源计数”。点测、尿量和检验合计仍最多1000项，撤销成员也计入，超过正文预算拒绝而不截断。来源或映射已撤销时列出排除原因，不充当有效测值。同刻且同项目、同精确身份的重复或原值/参考资料冲突分别展示，不取最后一条、不平均、不把定性转为数值。来源治理通过仅表示可以审查此受控子集，`model_input_validation`仍为`not_provided`，不证明全套检验齐全、已确诊或无风险。

风险输入采用`risk_lab_projection_v1`：省略完整父报告正文及申请的自由检查文字，保留结构化原值、原clock、人工核实说明和来源/映射证据；人工说明仅作来源依据。完整原文仍受原资料和来源哈希约束，删改被省略的正文也会使旧窗失效。原始来源快照单独有262144 UTF-8字节上限，MySQL新列用MEDIUMTEXT；超限在写入和审计前拒绝，不静默截短。窗口和模型请求还受各自的更小预算约束。

## NEWS2 固定规则与明确原点测

第41项`deterioration_risk`已接入独立的NEWS2计算服务，保留其他专用预警适配器的原窗口模式。配置为`specialist`且实际模型标识以`news2:`开头时，NEWS2界面预览与评分任务均须同时提交`observation_window_id`与`news2_assessment_id`；42新增独立qSOFA模式并保留外部专用服务原窗口模式，43另见下节AKI模式，均不接受NEWS2评估引用。当前目录/独立Prompt版本`2026.10.20.8`，80项Prompt、31个稳定引用键（新增原支持资料双引用仅用于第47项）；旧v1/v2内容和哈希配方保留，v2字节容量另见下节。通用资料API仍可仅凭窗口引用查看原窗，不返回NEWS2评分，也不能绕过评分任务的双引用要求。

### 规则审核与来源核实

超级管理员在“AI管理→风险规则与评估”建立固定`news2_2017`实施草稿，核对规则配方、输入策略、实施条款及真实审核依据后单独发布。同一规则同时仅允许一个发布版本，撤销须核对当前版本且不可恢复；不提供任意阈值或代码编辑。规则发布与服务能力检查均不修改功能的临床验证、启停或角色配置。

业务人员在已明确选择的原住院观测窗中，另选一个原点测，填写观察时年龄与依据、妊娠状态与依据，并明确选择血氧分表。服务器重核原患者、住院照护权限、窗口/点测/规则的原文、版本、摘要与状态；不选择“各项最新值”、拼接异时测量或让作者身份自行授予访问权。人工填写的适用性资料保留核实人及依据，但不是系统独立验证的病史或历史医嘱。没有完整来源正文的元数据目录不能直接作为评分输入或结果依据。

Scale 2还需血气证实高碳酸血症呼吸衰竭、明确临床决定及各自依据；本软件的签署权限策略另要求填写者有实际医生身份、相应角色和当前住院照护权限，超级管理员的全院治理权不能替代这些条件。护士可在当前照护范围复用已核实来源，但不能自行作出Scale 2决定。原作者后续角色变化不改写历史资格快照；其原医生身份重归属则使来源失效。血气证实及明确临床决定的要求依据[RCP 2020补充实施指南第5节](https://www.rcp.ac.uk/media/umzn4ntq/news2_additional-guidance-002-_0.pdf)，不能仅凭COPD或88–92%目标范围推定适用。

### 数值与缺项

原数量保留十进制文本。本实现的输入精度策略要求呼吸/血氧/收缩压/脉率为数学整数、体温满足0.1°C精度，可保留无影响的尾零；超出时不舍入、不补值。这是软件接入策略，不宣称原指南禁止设备提供额外精度。原AVPU的alert没有核实新发意识混乱，不能直接当ACVPU alert计0分；相关冲突、未知吸氧及未测分别保留。

## 成人AKI已观测判据与原资料

### 明确选择和人工核实

评估绑定同一患者、原住院、原冻结窗、审核发布的规则及完整原件哈希。须明确观察时年龄与依据；本实现只支持成人，未满18岁和维持透析超出范围。肌酐分别选择index、48小时比较和已知基线，确认确为血清/血浆肌酐；仅项目映射为肌酐不证明该用途。保留原已存Decimal数量、单位、命名空间、方法、标本、原UTC采样和登记可用时刻；不自动择最新/最低值、不反算基线或转换单位。比较要求原单位与完整检验身份一致。定性原文留在完整原件，任务不把它强转数值；非正数或不支持单位保留原数量而相应判据未知。

### 判据和缺项

肌酐核对48小时绝对变化、7日基线倍率与绝对3期急性前提。SI绝对变化使用指南的26.5 μmol/L；绝对3期采用原表2的353.6 μmol/L，正文另有四舍五入的354表述。绝对高肌酐需肌酐轴支持急性变化，不能只因稳定高肌酐加尿量异常升级为该项3期。不同单位不互换，完整阈值及边界证据见固定配方和专项测试。

尿量最多明确选择64个原区间，保留原UTC边界、原mL、完整性和患者总量声明。软件采用明确审核的`whole_original_interval_average_v1`：仅在完整连续原区间链上，以精确有理数核对区间平均速率，不分摊、插值或把均值称为每小时持续低值。体重须有明确原kg点测、早于所选尿量段，并人工核实整段适用；0保留但不能作除数。完整12小时零尿量可核对无尿判据，无需推测体重。体重选择和区间平均是本地输入策略；[KDIGO 2020争议会议报告](https://kdigo.org/wp-content/uploads/2018/02/KDIGO-AKI-Controversies-Conf-FINAL.pdf)讨论了这些操作差异，没有统一确定本软件的选择。

所选段内的重叠或漏选活动原区间使尿量轴不能可靠计算。可明确定位的间隙、未测或不完整区间拆分有效连续链，不能跨缺口累加；合法链中的已满足判据仍保留，缺口单独列出。其他轴未知不能抹掉阳性；1/2期注明最低分期，3期仍不证明完整病程。窗口之前的旧急性RRT保留原声明供审计，该项保持未知，其他阳性正常保留；这是软件所选事件范围，不能解释为KDIGO临床病程只限于本窗口。

## qSOFA原床旁核对与通用GCS来源

第42项`sepsis_risk`新增独立`qsofa:`规则服务。服务配置为`specialist`且实际标识以此开头时，预览和任务均须同时选择原`observation_window_id`与医生核实的`qsofa_assessment_id`。其他登记的外部专用服务继续走原观测窗模式，不能消费qSOFA评估。此批交付三项确定性资料核对及GCS原始来源，完整SOFA、脓毒症诊断、概率预测和治疗推荐仍需分别实施与验证。

### 通用原始GCS与明确同次检查

“原住院观测→原GCS”登记眼、言语和运动三个实际整数分项，或逐项明确`not_testable`/`not_recorded`。仅三项均实际测得时派生总GCS，不能把NT记1分或给出总分；依据见[GCS官方FAQ](https://www.glasgowcomascale.org/faq/)。AVPU/ACVPU、旧ICU/PACU分项、文本或AI推测不自动转为这份原GCS。

原件具有原患者、住院、实际观察UTC、系统登记UTC、完整内容摘要及独立治理版本。护士、医生或主任须有实际当前照护关系；超级管理员同样需要实际医生身份和原住院照护权限才能登记，服务端`can_record`/`can_revoke`控制操作。纯超级管理员可审计与撤销，不能代替临床记录资格。

原GCS可以独立保存；用于qSOFA时，须明确引用同次检查的一个原点测ID与完整摘要，确认同次检查并保存依据。两个真实观察时刻可不同，界面保留原时间，不改成相同时间、不按最近记录自动配对。GCS及点测的观察须在原窗内，系统登记均须不晚于原`as_of`。固定同锚集合包含截止时已经登记的所有原GCS及其治理状态，活动分项冲突时意识项未知；晚于截止登记的原件不泄漏存在、数量或内容。

### 医生当前回顾性核实

每份qSOFA评估均由当前有实际Doctor身份和原住院照护权限的临床人员核实原观察时的年龄、实际非ICU场景、疑似/明确感染及各自依据；GCS可解释性单独核实。签署记录当前服务器时间、当时资格和原观察适用时刻。护士可按当前原住院权限复用有效评估；额外AI资料访问授权本身不赋予Doctor身份或临床签署资格，权限仍按现有照护关系或有效限期授权核验。原作者身份本身不授予访问权。

原观测窗截止与后来临床核实分开保存：`review_mode=current_retrospective_review`、`historical_prediction=false`；`clinical_statements_recorded_at=evaluation_at=created_at`可晚于`as_of`。这份记录不证明较早截止时已经知道感染，也不是历史as-of预测。界面与固定解释持续展示此边界，不回填时间或把当前诊断拼入原窗。

### 固定三项与缺项表达

本实现按[Sepsis-3原共识](https://jamanetwork.com/journals/jama/fullarticle/2492881)核对：呼吸频率≥22/min、收缩压≤100 mmHg、实际完整GCS<15，各满足一项记1。呼吸/收缩压来自明确同一原点测；使用原十进制字符串及原单位，不舍入、不换算，真实0不当缺失。GCS不用早期模型推导中的≤13阈值。

本版核实范围为成人≥18岁、实际非ICU且疑似或明确感染。范围未知或明确超出时保留原量、各分项及总数未知。范围已核实且三项可计分时总数0–3；缺项时总数为空，至少一项可评分才给已知小计。已知两项阳性即保留“至少两项”的提示，其他缺项不能抹掉已有证据；缺项小计<2不能当完整低分或排除结论。NT、缺测、受限可解释性和同锚冲突均明确列出；分项完整但受限时保留原GCS合计供核查，不用其计意识分。

[SSC 2026成人指南](https://www.sccm.org/survivingsepsiscampaign/guidelines-and-resources/surviving-sepsis-campaign-adult-guidelines)优先推荐其他规定工具作为单一筛查工具，不能把本qSOFA核对当作单一脓毒症筛查。输出不提供诊断、排除、个体概率、SOFA、自动抗菌治疗或液体/升压药处置；Prompt不改变固定数值和解释。

专用契约v8只发送类型化qSOFA来源和完整Prompt，`store=false`；原患者/住院ID、完整窗口、原备注、临床核实依据正文及自由问题不外发。任务私有快照保留所选原量、明确同锚集合、完整原件摘要与依据摘要，原始完整件另存；证据按同一冻结来源的固定白名单索引展开。网关重算每项、总数/下界、适用性、时间、版本、引用及整份固定解释，篡改或追加概率均拒收。

排队、在途回执与普通历史均重核当前原住院照护、Doctor身份关联、原窗、点测/GCS/同锚集合、规则和临床声明；排队/在途失效时不接收保存新回执；既有结果拒绝普通读取，超级管理员保留冻结审计。来源登记、发布/撤销与审计同事务，当前版本竞争不覆盖原件。迁移`20261020_qsofa_sources`仅新增两表及六个UTC `DATETIME(6)`字段，不转换旧ICU钟点、不修改旧表或原窗哈希；单链父版本为`20261020_ai_aki_sources`。完整原件、输入、证据和结果按各自UTF-8字节上限拒绝过大内容，不截断。工程验证及合成资料不能代替独立临床验证，功能不会因此自动启用。本批最终源码、测试、容器、隔离MySQL与历史原件摘要见[qSOFA/GCS工程验证](ai-qsofa-verification.json)。

## 原器官支持资料与单条交班整理

住院观测窗的“原器官支持资料”入口新增五类独立原件：直接测得的MAP、呼吸支持核实区间、动脉血气与FiO₂明确配对、血管活性药实际给入区间、医生感染episode声明。原始数量使用十进制字符串，零值、未测原因和null分别保存。临床观察、实际给入/支持区间与服务器登记UTC分别保留，不把当前人工回顾当作历史截止前已知。登记或撤销原件后须重新选择原窗。

MAP须有实际测量方法和依据，不用收缩压/舒张压推算。支持区间须核实连续性、起点和明确可核实终点；已停止使用左闭右开区间，仍在支持只涵盖已核实截止。血气配对明确选择同住院的PaO₂检验、FiO₂点测和支持原件，各自完整摘要及真实时刻保留，不按最近时间猜配。当前医生分别确认动脉样本、同次采样状态及FiO₂适用性；未确认或未知值可保留，尚不计算P/F比值或SOFA。

给药资料明确选择超级管理员审核的实际药物身份映射，记录base/salt/unknown和允许的原单位。三个独立剂量输入为按体重速率、绝对速率和泵速/浓度，保留实际量，不自动换算、合并去甲肾上腺素当量或认定已满足一小时。原体重点测需明确适用；实际eMAR引用绑定已执行给药、执行记录、原医嘱与药品明细全链。旧eMAR无时区钟点原样保存并标注未知历史可用性，不推算连续UTC给入区间。

感染episode的所有状态（包括unknown）均须当前有实际Doctor身份及原住院照护权限的人员签署。临床范围、首次疑似与发作时刻分别记录；未知发作时刻保持null。可明确选择当前同住院的受控检验或最新已签结构化病历诊断复核，冻结完整原件及摘要；可靠检验采样、登记及可用时刻不能晚于episode登记。旧诊断钟点不升级为可靠UTC历史可用时间。该声明不推断感染所致器官变化、基线或Sepsis-3诊断。

“使用本条资料整理交班”接入第47项`handover_summary`，同时绑定`support_source_id`与`support_source_kind`；其他79项不接受这两个引用。本模式仅整理明确选择的一条原件及其直接关联，保留原量、原单位、零值、未知与原时刻，不代表完整交班、24小时最差状态、完整SOFA、脓毒症诊断、概率或治疗建议。未带这两个引用的原交班模式继续使用既有资料。第47项独立Prompt已更新，目录版本`2026.10.20.8`、80份独立默认Prompt、31个稳定引用键。

文本网关使用实际Chat或Responses配置。私有任务快照保存完整原件、临床依据和父件；模型仅收到白名单原量投影、固定范围说明和已绑定证据，不外发原患者/住院ID、完整原备注、诊断原文、药品条码、医生资格全文或自由补充问题。队列执行、在途回执和普通历史重核当前原件、直接依赖、签署Doctor关联及照护权限；变化后普通读取失效，超级管理员仍可核查原冻结审计。模型草稿须人工复核，输入绑定检查不代表对生成文字的临床正确性验证。

超级管理员的“AI管理→原器官支持资料”提供五类全院分页原件、完整冻结依据、失效原因和按版本撤销，以及独立血管活性药映射的草稿、审核发布与撤销。原照护人员按范围登记/读取，原作者按当前照护关系撤销；管理员身份或额外AI资料访问授权本身不赋予Doctor签署资格。全部80项的模型、独立Prompt版本、角色、额度、知识、启停、验证及任务审计仍沿用统一超管管理，不随来源登记或映射发布自动启用。

迁移`20261020_organ_support_sources`仅增加六张独立表、18个UTC微秒字段和五个有界MEDIUMTEXT引用列，单父版本为`20261020_qsofa_sources`。不修改旧表、既有原窗或历史哈希配方；五类原件每份payload上限32768 UTF-8字节、完整内容上限262144字节，组合任务输入及结果仍受各自TEXT上限约束，超限明确拒绝而不截断。完整SOFA多器官规则、基线变化与感染归因仍属后续实施范围。最终4333项后端、374项浏览器、隔离MySQL及64份实现/生成物摘要见[原器官支持资料工程验证](ai-organ-support-verification.json)，合成工程验证不代表临床效果验证。

## 医疗语音录入与录音治理

“医疗语音录入”现在需要选择已授权患者和明确的`audio_asset_id`。门诊和住院病历行各有独立的“AI 录音转写”，固定原患者与所记就诊；不沿用病历正文作为语音识别输入。工作台也可选择已有录音。转写只自动提供所选原录音与其技术资料，不附带其他临床历史；用户补充问题不能当作实际听到的发言。

1. 展开“登记新录音或使用麦克风采集”，核对患者、所记就诊及录音采集和处理授权，明确勾选并填写说明。说明为登记人的核对记录，不表示系统独立核实了授权或真实身份。
2. 选择授权原文件，或主动点击“开始录音”。麦克风依赖浏览器能力及安全上下文；采集使用浏览器报告支持的编码，停止后仍需单独登记。切换患者或就诊、关闭面板及离开页面会停止采集并丢弃未登记录音；上传迟到回执不会绑定新患者。
3. 文件登记成功后明确选择原录音，先查看本次资料和原音，再提交转写。上传、目录读取和听音不创建模型任务。原文件时间可留空；提供时须有时区，不用上传时间补写。浏览器采集的时间来自采集端时钟，未独立核验。
4. 配置本功能的专用语音服务、患者资料传输权限及验证记录。原音可能含直接标识；提交转写会把原音附件发送给所选服务。默认未启用临床能力，超级管理员仍需按原流程配置和评审。
5. 结果显示相对解码音频的片段时间、说话人分组及不确定说明，可听对应片段、查看元数据引用并复制完整转写草稿。说话人身份与职业保持未知；不能据标签认定医生意见或患者陈述。片段范围校验不证明转写完整或识别准确，须听音核对后再走原文书书写和签署流程。

支持WAV、MP3、M4A、Ogg/OGA和WebM的单一纯音频轨。服务端检查固定格式、声道/采样资料和实际解码输出，浏览器WebM未保存时长头也可校验；解码校验不改写或保存处理后的副本，原字节与哈希保留。文件名不写入登记元数据；原容器和声音本身仍可能有识别线索，不构成匿名化。私有文件采用0600权限，目录0700，不经通用报告下载命名空间提供。

| 配置 | 默认值与作用 |
| --- | --- |
| `AI_AUDIO_STORAGE_DIR` | `private/ai-audio`；API与worker共享且可读取的私有目录，必须与上传和Web静态目录分开 |
| `AI_AUDIO_MAX_BYTES` | 67,108,864（64MiB）单文件上限 |
| `AI_AUDIO_MAX_DURATION_SECONDS` | 3600秒实际解码时长上限，需与模型验证范围相符 |
| `AI_AUDIO_USER_QUOTA_BYTES` | 536,870,912（512MiB）每登记人额度，按未清除的登记原文件字节计算 |
| `AI_AUDIO_PROCESS_TIMEOUT_SECONDS` | 30秒原格式探测/解码处理时限；超时明确失败 |

镜像安装FFmpeg，Compose的API与worker共享`ai_audio_private`卷并使用同一路径；私有目录及通用上传资料排除于镜像构建上下文。Nginx支持录音表单开销、同源麦克风和本地Blob播放；前端读取原音经`accesstoken`请求头鉴权，令牌不放入播放URL。关闭音频窗口或切换来源会停止播放并释放临时链接。格式处理参考[FFmpeg协议限制](https://ffmpeg.org/ffmpeg-protocols.html)与[ffprobe资料读取](https://ffmpeg.org/ffprobe.html)，浏览器采集使用[MediaStream Recording](https://www.w3.org/TR/mediastream-recording/)接口。

录音限登记人与超级管理员在当前诊疗关系或有效用途授权内使用；患者用途授权不转移他人登记的录音。功能使用角色配置另行限制登记和转写，普通管理员不能管理全院录音。超级管理员在“录音治理”中检查原授权说明和元数据、撤回及按版本清除原文件。撤回不释放文件额度；清除流程先持久化“清除中”，成功删除后标记“已清除”，存储失败可按当前版本恢复。原撤回原因与原清除原因分别保留。

撤回会阻断排队任务，在途结果重新检查后拒收；原文件、录音版本、当前诊疗关系或适用科室变化也会停止旧任务或拒收结果。已报告用量仍保留。普通用户不能继续读取已撤回来源的旧转写，超级管理员可追查冻结文字和元数据；原文件清除后不能播放。撤回无法收回已经发出的服务请求或已读取资料，清除当前原文件不会删除审计和既存任务文字。

录音接口：`GET /api/ai/audio-options`、`POST/GET /api/ai/audio-assets`、`GET /api/ai/audio-assets/{id}`、`GET /api/ai/audio-assets/{id}/content`、`POST /api/ai/audio-assets/{id}/withdraw`。全院目录与原文件清除分别为`GET /api/ai/admin/audio-assets`、`POST /api/ai/admin/audio-assets/{id}/purge`，仅限超级管理员。状态操作须有`expected_revision`和明确原因；内容变更与患者/就诊重绑不通过更新原文件实现。

## 专用适配器契约

配置类型为 `specialist`，登记实际模型版本、支持的功能 key 和验证报告。平台向配置基础地址的 `/tasks` 发送：

```json
{"schema_version":"1","feature_key":"ecg_analysis","engine":"signal","model":"实际模型版本","instructions":"实际冻结的固定系统Prompt与任务Prompt","input":{"input":{},"context":{},"tools":{},"evidence":[]}}
```

适配器必须核对适用人群、原始资料类型和输入质量。响应包含 `schema_version`、相同的 `feature_key`、与配置一致的 `model_version`、布尔值 `applicable` 以及 `result`。`applicable` 不为 `true` 时任务失败，不退化为大模型编造结果。

`result` 的结构与文本任务一致：`summary`、`sections`（每项含 `title`、`content`、`source_ids`）、`warnings`、`missing_data`。原始图像、波形、数字切片、带结局标注的队列及模型性能必须由具体适配项目提供和验证；此接口契约不替代这些工作。

### 语音附件契约v2

`medical_transcription`使用同一`/tasks`路径的`multipart/form-data`：`task`部分为JSON，含`schema_version:"2"`、功能、引擎、实际模型、完整`instructions`、`store:false`及冻结的`input`；`audio`部分为经核实的原文件，文件名为固定`recording`加原格式后缀。`input.context.audio_source`和`evidence`给出原文件标识、SHA-256、字节数、解码时长、采样与声道、版本和引用标识，不传私有磁盘路径或凭据。

接收端须校验实际收到字节的SHA-256、长度、原格式及模型适用范围，只解码该附件，不抓取输入中的任意URL。`store:false`是接收端需落实的处理约定，客户端标记不能证明服务实际保留策略。响应示例：

```json
{
  "schema_version": "2",
  "feature_key": "medical_transcription",
  "model_version": "与登记一致的实际模型",
  "applicable": true,
  "result": {"summary": "待听音复核的转写草稿", "sections": [], "warnings": [], "missing_data": ["说话人角色未经核实"]},
  "transcription": {
    "asset_id": "原录音UUID",
    "content_hash": "实际收到原文件的64位SHA-256",
    "time_basis": "relative_decoded_audio",
    "speech_detected": true,
    "language": "zh-CN",
    "segments": [{"start_ms": 0, "end_ms": 200, "speaker": "speaker_1", "speaker_role": "unknown", "text": "实际识别且待核对的内容", "uncertain": true, "uncertainty_note": "具体不确定处", "source_id": "提供的原音引用标识"}]
  },
  "usage": {"input_tokens": 5, "output_tokens": 7}
}
```

分段使用严格的整型毫秒，按开始时间排序且不超过原解码范围，可保留重叠发言。每段引用必须是该原录音，身份角色只接受`unknown`，不确定片段须给出说明。声明未检出语音时须为空片段。响应仍受512KiB及1000段上限约束，超限失败，不静默截断。输出不合法也保留已经正确解析的服务报告用量。上述JSON只是协议示例，不是识别质量或验证数据。

本地`fw:`模型另须返回`transcription.processing`，外部v2适配器未提供时界面明确显示处理范围未知。处理报告包含`engine`、`engine_version`、固定40位`model_revision`、`model_digest`、`runtime_digest`、`decoding_options_hash`和本次完整系统及任务Prompt的`instructions_digest`，以及`decoded_duration_ms`、`processed_duration_ms`、`submitted_samples`、`sample_rate`、`iterator_exhausted`、`vad_filter`、`translation`、`diarization`、`prompt_handling`、`timestamp_policy`。平台核对实际登记模型、原音时长、16kHz样本计数、完整迭代及本次Prompt哈希；不接受只处理部分输入的本地结果。完整处理是服务对输入范围的报告，不证明逐字完整、VAD无漏检或医学识别准确。

### 可选本地CPU语音服务

仓库提供`app.ai.speech_server`和独立的识别子进程。API与业务worker仍通过已登记的`specialist`网关调用，不要求给主业务运行环境安装识别依赖；默认不启动服务或启用临床能力。模型只从经核实的本地文件加载，推理启用离线模式，不接受请求中的模型路径或URL。一次最多处理一份原音，繁忙时明确拒绝而不重复排队；识别超时或进程任务取消时终止子进程组，临时原音与响应文件在处理结束后释放。

运行依赖在`requirements-speech.txt`固定；实际权重清单、各引擎库版本、语言、解码配置和CPU线程数共同形成`fw:<运行哈希>`。准备工具要求明确的仓库及40位提交哈希，复制并校验配置、权重、tokenizer和词表，不覆盖原版本。文件、依赖或识别配置变化须登记新的实际模型标识；服务核对与实际任务均不静默使用其他版本。

下面的小模型仅供非临床工程联调，不能据此选择医疗生产模型或推定中文术语效果。示例权重来源及许可见[固定版本模型卡](https://huggingface.co/Systran/faster-whisper-tiny/tree/518d6e0b5a068b278f66842b17377f9523de5cd1)，引擎行为参考[faster-whisper官方实现](https://github.com/SYSTRAN/faster-whisper/tree/v1.2.1)。

```bash
cd fastapi_be
python -m venv .venv-speech
.venv-speech/bin/python -m pip install -r requirements.txt -r requirements-speech.txt
.venv-speech/bin/python scripts/prepare_speech_model.py \
  --repository Systran/faster-whisper-tiny \
  --revision 518d6e0b5a068b278f66842b17377f9523de5cd1 \
  --destination "$PWD/private/ai-models/engineering-tiny"

# 先通过部署系统注入AI_PROVIDER_LOCAL_SPEECH_API_KEY，至少32字符的独立随机密钥。
# API/worker如使用环境变量引用，也须注入相同变量；不要把密钥写入Prompt或版本库。
export SPEECH_MODEL_DIR="$PWD/private/ai-models/engineering-tiny"
export SPEECH_LANGUAGE=zh
.venv-speech/bin/python -m app.ai.speech_server --describe
.venv-speech/bin/python -m app.ai.speech_server
```

服务配置示例为`.env.speech.example`，进程仅读取已导入的环境变量，不自动加载该文件。默认语言`zh`、CPU int8、4线程、beam size 5、单文件64MiB、300秒原音、110秒识别处理时限；模型冷启动计入处理时限，传输和登记校验开销另计。依赖FFmpeg，处理失败返回明确错误。`--source-dir`可从已有离线目录准备模型，不发起模型下载。

超级管理员在“模型服务”中登记类型`specialist`、适配功能`medical_transcription`，基础地址为同主机运行时的`http://127.0.0.1:8810`，密钥引用`AI_PROVIDER_LOCAL_SPEECH_API_KEY`或录入相同的加密保存密钥，模型标识使用`--describe`返回的实际值。请求超时设为120秒以覆盖110秒识别时限及部分传输开销。服务自身的语言、时长和资源配置属于部署参数，临床评审需记录其实际范围。

“检查本地语音服务”只对已保存配置执行鉴权`GET /capabilities`，不发录音、患者资料或模型推理；API接口为`POST /api/ai/admin/providers/{id}/speech-capabilities`，须有`expected_revision`，且仅超级管理员能调用。检查前后核对当前管理角色和配置版本，报告只显示已定义字段，不回显密钥、磁盘路径或任意服务响应。实际模型或请求超时不匹配时展示差异；“填写实际模型，待保存”只填写表单，保存与后续评审仍需分别执行。检查不会更改启用状态或登记临床验证。

该引擎执行声学转写，不把完整系统/任务Prompt、用户问题或病史作为`initial_prompt`或热词来补写发言；报告`prompt_handling: acoustic_only`。识别前核对实际模型支持的配置语言，拒绝英语专用模型把中文配置静默改为英语。保持原识别词句并逐段标记待核对，不区分说话人，统一`unknown`。若模型末尾估计超出原音，听音区间限定在实际范围，并在不确定说明中保留原估计值；`timestamp_policy: estimated_bounded_to_source`表示估计时间，不是人工对齐。VAD可能漏检；未返回片段不证明原音无人发言。真实术语、说话人和医疗质量评估仍未完成。

可用`Dockerfile.speech`单独构建运行镜像，主识别权重通过外部只读目录提供，不打包进应用镜像或Git；VAD资源随固定的识别依赖安装。镜像以非root用户运行，挂载目录需允许该运行UID读取；建议只读根文件系统与独立临时目录。镜像默认监听容器内8810端口，跨主机或容器调用需受信任HTTPS端点并加入原`AI_PROVIDER_ALLOWED_HOSTS`，可使用`--ssl-certfile`和`--ssl-keyfile`或已有TLS代理。容器内`127.0.0.1`指自身，不能直接当作另一个容器地址。没有修改现有Compose来默认启动或发布语音服务。

`scripts/smoke_local_speech.py`只生成固定的非临床英文合成语音及静音，检查WAV、WebM原字节传输、真实本地识别、完整输入报告与静音结果；它不接受实际患者录音。`tests/test_ai_local_speech_real.py`另用隔离数据库和合成患者，验证登记→排队→worker真实识别→冻结结果→授权读取，确认没有修改病历。默认测试不下载权重，该项需显式选择已准备的模型；两种检查均不构成中文、药名剂量、重叠发言或临床质量评估，也没有调用付费模型。

2026-10-20已实际构建该镜像，并在禁用网络、只读根目录、UID10001、4CPU/2GiB及独立临时目录的容器中通过3项检查：3.94秒WAV与WebM均识别出固定句子的四个核对关键词，0.25秒静音未返回片段。容器内153个Python源码文件与当时工作区哈希逐项一致；本地Python3.13环境和镜像Python3.12环境的依赖差异各自进入实际运行标识。详见[离线试跑记录](ai-speech-smoke.json)，其中只保存合成文本、实际版本和工程验证边界。

## 原始心电接入、候选复核与治理

编号37“心电辅助分析”使用明确的`ecg_asset_id`。门诊、住院病历行的“AI 心电复核”固定原患者及已记就诊，不把病历正文、检验文字、报告截图或外部URL当作原波形。工作台可以另选同患者的已登记记录。预览只提供原采样技术资料与独立引用；原头注释、原文件名、登记授权说明和无关病史不发送给模型。原采集时刻未知时保持未知，头文件时钟没有时区或核验依据时不升级为已确认采集时刻，也不按今天年龄推定采集人群。

### 当前支持的原文件

当前接收单段、单`.dat`文件的WFDB格式16（有符号16位小端、按导联交错），原`.hea`和`.dat`名称必须对应。每份1–16导联，采样率50–10000Hz，须显式声明样本数、导联、正增益、基线或ADC零值、物理单位、初值和校验和；不采用缺省增益或单位。识别标准导联及明确的MLII/MCL1/VX/VY/VZ标签，MLII不改成II。不接收212压缩、跨文件、多段、非零偏移/延迟或不同导联频率，不静默重采样、导联补全或截断。

原数字值`-32768`保留为缺失，不按0参与有效幅度或恒定值计算。校准按`(ADC－基线)/增益`及原单位换算mV，支持mV、uV/µV/μV和V；校验和按原数字样本核对。返回原初值声明和实际观察，不把恒定采样判为心搏停止或证明信号有效。全部导联只有缺失采样时仍可核查登记资料，但不能创建判读任务。格式校验、显示幅度与模型覆盖报告均不构成设备、信号质量或诊断验证。

格式解释参考[WFDB头文件规范](https://wfdb.io/spec/header-files.html)、[原采样格式规范](https://wfdb.io/spec/signal-files.html)及[官方Python读取接口](https://wfdb.readthedocs.io/en/latest/wfdb.html)。可选的`requirements-ecg-verification.txt`只安装格式对照库，不是诊断模型。`scripts/verify_ecg_wfdb.py`使用固定合成数字值、三种单位和不同基线，与WFDB 4.3.1对照：原导联顺序、缺失位置及mV换算一致。验证记录见[心电工程验证](ai-ecg-verification.json)，没有使用实际患者心电或评估疾病识别。

### 登记、读取及超管管理

`POST /api/ai/ecg-assets`以multipart提交`header`、`signal`、`patient_id`、可选`encounter_ref`、`authorization_confirmed`和至少5字的`authorization_note`；可选`recorded_at`须带时区，服务端统一UTC。先校验当前患者/原就诊权限，再解析文件，登记前再次核对当前角色、授权、配额和资料。原文件用独立私有目录保存，目录0700、文件0600，校验与登记不调用模型。不能将`AI_ECG_STORAGE_DIR`放在公开上传目录内。

| 项目 | 当前行为 |
| --- | --- |
| 使用角色 | 超级管理员、医生、科主任；检验技师另需当前有效、诊断用途的限时患者授权，普通检验单不自动授予原心电读取权 |
| 团队共享 | 当前具备原患者及原就诊诊疗权限的成员可读取他人登记原文件；撤回仅限登记人及超级管理员 |
| 文件额度 | 默认32MiB/份、300秒、512MiB/登记用户；`AI_ECG_MAX_BYTES`、`AI_ECG_MAX_DURATION_SECONDS`、`AI_ECG_USER_QUOTA_BYTES`可配置，撤回未清除的原文件仍占额度 |
| 原波形 | 鉴权`GET /api/ai/ecg-assets/{id}/window`，以原样本`start_sample`、`sample_count`及每导联点数`max_points`请求；保留原索引，概览保留极值并断开缺失区间 |
| 原文件导出 | 鉴权`GET /api/ai/ecg-assets/{id}/content?part=header\|signal\|pair`；pair为保留原文件名及原字节的ZIP，便于另行读取。原头注释可能含身份资料，仅明确操作时导出 |
| 撤回与清除 | 撤回和超管清除均要求`expected_revision`及原因；先持久化清除中状态，再删除当前原文件，失败可按新版本继续且保留首次清除说明 |
| 已有任务 | 原文件、当前诊疗关系、来源状态或版本变化会停止旧队列调用或拒收在途结果；普通用户不能继续读取失效来源的旧结果，超管仍可追查冻结快照 |

登记选项为`GET /api/ai/ecg-options`，患者目录为`GET /api/ai/ecg-assets`；超管目录和清除分别为`GET /api/ai/admin/ecg-assets`及`POST /api/ai/admin/ecg-assets/{id}/purge`。超管“心电原文件”页可查看原授权说明、按版本撤回及清除恢复，原文按纯文本显示。原波形和导出只在用户点击后读取，鉴权Token使用请求头，URL不含Token。关闭或切换来源会清理视图，迟到的上传、读取或定位回执不覆盖新患者和当前窗口。

API与worker必须共享`AI_ECG_STORAGE_DIR`；Compose已配置独立`ai_ecg_private`卷和相同额度，前端代理为成对上传保留最高128MiB及表单开销。清除删除当前存储原文件，任务文字、元数据及审计保留；撤回不能收回已发出的请求或已下载资料。

### 心电附件契约v3

该功能只接受`specialist`服务，不能回退到通用文本模型。网关发送multipart到已登记服务的`POST /tasks`：`task`为带完整系统/任务Prompt、原始技术资料、输入与引用的JSON字段，`waveform`为原始16位小端采样附件，固定文件名`signal.dat`。不发送磁盘路径或原头注释。服务必须按原导联数、原顺序、原采样率和校准参数解释附件，并核对所传文件哈希及其适用人群。

### 可选本地CPU心电研究模型

已接入[Tumo505固定发布](https://huggingface.co/Tumo505/SSL-ECG-Classification-model-card/tree/6ec2ee1a1badd9508f9c1219fb07de38f3f6936b)的实际权重，代码与模型采用Apache-2.0。仓库保留完整许可与改动说明于`fastapi_be/third_party/ssl-ecg/`。本地实现参考[原始PyTorch架构](https://github.com/Tumo505/SSL-for-ECG-classification/blob/6b82956004c0ffa7ae6e983df7867eec1b450d85/src/ssrl_ecg/models/cnn.py)及[固定版本推理实现](https://huggingface.co/Tumo505/SSL-ECG-Classification-model-card/blob/6ec2ee1a1badd9508f9c1219fb07de38f3f6936b/inference.py)，移除Transformers及远程Python加载；运行时只加载已审查的本地代码和固定safetensors字节，不使用pickle权重。训练或性能数字属于发布者报告，本项目未将其作为本院临床验证。

该模型严格使用原100Hz、每导联1000样本的完整10秒标准12导联：`I, II, III, aVR, aVL, aVF, V1–V6`。可按实际名称重排原导联，按原增益、基线和单位换算mV；缺失导联、实际缺失样本、其他采样率或长度均拒绝，不补值、生成导联、滤波、重采样、裁剪或填充。500Hz原记录仍可登记及查看，需要另行配置支持其原始输入的服务，不能声称该研究模型已验证重采样。模型的`applicable`仅报告此技术输入范围，采集时人群、设备及临床适用性仍需核实。

预处理与原发布一致：先转NumPy float32，再逐记录逐导联减均值、除以总体标准差；标准差下限`1e-6`，不是相加epsilon或无偏标准差。实际网络为六组Conv1d/BatchNorm/ReLU、全局平均池化及五类输出，539,909个可训练参数、38个状态张量。固定返回`NORM、CD、HYP、MI、STTC`五个独立sigmoid原分数及整段级位置，不应用0.5诊断阈值，不把NORM解释为已确认正常或把其他低分作疾病排除，也不生成精确起止定位。

## 单帧DICOM原图、v4像素任务与超管治理

医学影像辅助识别（36，`imaging_detection`）现在要求真实 `image_asset_id` 和 `imaging_order_id`。影像检查页行入口固定患者和原申请；不能通过补充JSON换绑申请或把PACS调阅地址当像素。原申请没有就诊关联字段，所选就诊仍须按现有权限单独核对，不由申请日期推定。报告辅助起草（35）继续使用实际报告文字，病理切片（38）另需WSI来源与专用模型。

新接口使用当前医生/科主任的诊疗关系或真实申请医生关系；仅申请关系不授予其他功能的患者病历权限。技师须有当前患者的限时诊断授权，普通检验单不形成原影像权限。患者端和普通管理员不读内部原图。登记人及超管可按版本撤回；超管可查看来源核对说明、冻结任务、撤回和清除并恢复失败流程。原申请患者重新关联时拒绝原文件读取，超管仍可按原源标识治理。撤回、原文件变化、申请取消/变化或诊疗权限撤销会阻止排队调用、作废在途候选及普通用户旧结果。超管保留冻结审计；这不允许对当前失效来源继续推理。

| 接口（均以`/api`开头） | 用途 |
| --- | --- |
| `GET /ai/image-options` | 当前文件/像素上限及本人累计额度 |
| `GET /ai/image-orders?patient_id=...` | 按实际患者权限选择原申请；原检查号和部位文字只供人工核对 |
| `POST /ai/image-assets` | multipart字段`image`、`patient_id`、`imaging_order_id`、可选`encounter_ref`、明确来源授权核对及可选带时区`recorded_at` |
| `GET /ai/image-assets`、`GET /ai/image-assets/{id}` | 当前患者/申请来源及版本，详情含登记人的核对说明 |
| `GET /ai/image-assets/{id}/pixels` | 鉴权后的原坐标、小端有符号int32逻辑存储像素，含尺寸/摘要头，禁止缓存 |
| `GET /ai/image-assets/{id}/content` | 鉴权后的不改写DICOM原文件，使用不含原文件名的附件名 |
| `POST /ai/image-assets/{id}/withdraw` | `expected_revision`及原因，限登记人/超管 |
| `GET /ai/admin/image-assets`、`POST /ai/admin/image-assets/{id}/purge` | 超管患者/状态筛选及清除/恢复；清除中不继续读文件，保留首次清除请求和冻结审计 |

原件`source.dcm`和解码后的`pixels.i32le`位于独立0700私有目录，文件0600，不进入通用上传目录。读取时拒绝符号链接/非普通文件，校验原文件及实际像素哈希后使用同一打开句柄。`AI_IMAGE_STORAGE_DIR`默认`private/ai-images`，默认原件64MiB、16Mi像素、本人1GiB额度（包含原件及派生像素）；Compose的API和AI worker共享`ai_image_private`卷。未对真实数据库执行迁移或启动Compose业务服务。

当前接入范围是DICOM Part10、原生显式/隐式小端、单帧单样本、8/16位MONOCHROME1/2，支持常规CR/DX/CT/MR/MG单图存储类、明确有效位宽及线性重标定和窗参数。先以有限长度顶层扫描限制解析工作，再由固定pydicom3.0.2只读取白名单技术字段。压缩、未实现的LUT、未定义长度元素、多帧、增强影像或容积均明确拒绝，不取首帧或首张冒充完整检查。CT/MR单图可登记但不代表完整扫描，也不自动成为胸片模型适用输入。

解码仅提取BitsStored声明的逻辑存储值，清除未使用高位并进行明确符号扩展，不重采样、旋转、开窗或修改原件。模型只收到原坐标int32le像素与技术参数，不收到原始DICOM头、文件名、检查号或自由文本；Study/Series/Instance UID只保留摘要。头信息剥离不代表像素匿名化，`BurnedInAnnotation`是原声明。PixelSpacing与ImagerPixelSpacing分别保留，不据显示比例推测病灶实际尺寸。

前端只在显式点击后读取带当前鉴权的原像素，并核对实际SHA256。显示按原存储坐标，先线性重标定，再选择LINEAR/LINEAR_EXACT/SIGMOID窗，最后按已核对的MONOCHROME/PresentationLUT配对反转一次；padding在原存储值域掩黑。无预设时自动非填充最小/最大窗明确标为显示选项。支持人工窗位/窗宽、缩放平移及原行列坐标，未知方向不补写左右。8组独立pydicom窗函数对照包含窗内斜坡和中点；解码整数与独立`pixel_array`对照。

专用模型接口使用`schema_version="4"`，multipart包含完整`task` JSON及`image=(pixels.i32le, application/octet-stream)`；原始DICOM不发适配器。普通文本接口不会回退代替像素。响应外层要求功能、模型版本、`applicable=true`及普通结构化`result`；并列`image_analysis`包含原来源三种哈希、`coordinate_space="source_pixels"`、实际处理及候选：

```json
{
  "asset_id": "实际原图UUID",
  "content_hash": "实际组合SHA256",
  "original_hash": "原DICOM的SHA256",
  "pixel_hash": "实际int32le附件SHA256",
  "coordinate_space": "source_pixels",
  "processing": {
    "instructions_digest": "完整任务instructions的SHA256",
    "input_rows": 1024,
    "input_columns": 1536,
    "input_frames": 1,
    "processed_frames": [0],
    "analysis_region": {"x": 256, "y": 0, "width": 1024, "height": 1024},
    "preprocessing_notes": ["示例：实际居中裁剪后缩放；此处必须按真实处理填报"]
  },
  "findings": []
}
```

原来源/尺寸/Prompt必须精确匹配。分析区域为原像素半开矩形，候选真实矩形须位于实际处理区域内。图像级分类使用`location="image"`、`region=null`；有真实定位模型才可用`bounding_box`。原分数`score_kind="model_score"`不称患病概率，零分与未提供分别显示；未返回候选不代表正常。不生成虚构框、掩码、测量或完整检查结论，不改诊断或签署报告。完整独立Prompt仍可由超管管理版本；胸片接入批次目录版本为`2026.10.20`。

## 本地胸片v4研究服务与能力核对

`app.ai.imaging_server`现在可以接收医院网关发送的实际`pixels.i32le`附件，通过独立CPU子进程返回18项研究模型分数。`xrv_stored_range_v1`明确采用作者原生存储值帮助器路径；作者不同训练数据集的PNG/JPEG转换并不构成统一原生DICOM训练链，本实现不称训练等价或DICOM诊断显示。

| 项目 | 固定行为 |
| --- | --- |
| 原图声明范围 | 单帧CR/DX对应presentation存储类、CHEST、PA/AP、无符号8–16有效位、8/16位容器、恒等重标定；PresentationIntentType仅FOR PRESENTATION或未声明，拒绝FOR PROCESSING；源像素最大16Mi/64MiB |
| 强度 | 先核对实际小端int32逻辑值及源统计，再按原BitsStored最大值`2**BitsStored-1`做作者float32归一化；MONOCHROME1在此之前做一次`maxval-stored` |
| VOI及显示 | 原窗声明仍须合法，但模型研究输入明确不应用VOI窗、图像min/max或直方图均衡；阅片组件继续按其DICOM显示链独立开窗 |
| 背景 | 原padding沿原像素路径保留，不填补、不当病灶；报告全输入和实际裁剪区的padding/有效数量，裁剪区没有含变化的有效像素时拒绝 |
| 裁剪 | `side=min(rows,columns)`；`x=columns//2-side//2`、`y=rows//2-side//2`，保持作者整数中心公式；奇偶组合不能用`(columns-side)//2`替代 |
| 缩放 | CPU float32，原中心方形按torch bilinear、`align_corners=False`、`antialias=True`缩放至224×224；已224时不重采样，不旋转或翻转 |
| 数值边界 | 保留实际插值张量，固定0.01浮点舍入容差，不clip或伪造范围；原逻辑像素范围仍逐值精确校验。实测合法大图越界最大0.00146484375，越过工程容差仍拒绝 |
| 结果 | 完整18个原始sigmoid分数，图像级、无病灶框/掩码、无诊断阈值/概率校准；实际裁剪区外未分析 |

## 护理评估、ICU/PACU人工评分与AI原始依据

护理评估、护理计划、危重护理和ICU/PACU评分行已有固定患者、原住院及原资料的AI入口。交接班摘要可以整理实际记录；护理风险和计划草稿仍要求有效审核知识与临床功能配置。病情恶化、脓毒症和AKI有独立的输入与适用性要求；NEWS2、成人AKI和qSOFA固定实现另见上节，护理标记和人工分项合计不能替代其原资料、规则或预测模型验证。

### 未评估项与时间

| 来源 | 新记录行为 | 历史记录行为 |
| --- | --- | --- |
| 护理评估 | ADL、压疮、跌倒、意识、营养五项初始为null；0必须显式填写。草稿可继续填写，至少一项有原值才可完成 | 原ADL100、风险0等值原样保留，标`legacy_unverified`，不推断它们曾经过人工确认 |
| 危重护理 | 意识和GCS不预选；其他未知数值仍为null。GCS原总数没有三分项时不重新计算 | 不把旧GCS15、意识0升级为本版已核实结果 |
| 评估发生时间 | 护理评估及人工评分的`assessed_at`仅接受显式带时区ISO输入，规范为UTC；未知时为null | 不用创建、登记或更新时间补成发生时间 |
| 危重护理时间 | `record_time`带时区时规范UTC并记`time_basis=utc`；合法无时区旧输入保持`unspecified`；缺省只记`recorded_at_only` | 原时间保留，不推定医院时区；后两种不会填入AI evidence的`observed_at` |

护理新输入版本`nullable_v1`仅说明允许保留未知项，不代表量表、人工赋值或临床适用已验证。本地0–3风险标记及ADL数值没有标准量表版本与逐项答案，不能自动重算Morse、Braden或VTE量表。完成评估后继续沿用不可修改的原业务规则，不自动生成护理计划。

更新护理草稿时，省略字段表示保留原值，显式null表示清空；备注清空使用空字符串。相关四个前端请求显式JSON序列化，保留null，不让共享请求拦截器把清空动作删除。切换患者清空未保存输入，迟到列表和保存回执不能覆盖新选择；编辑中的草稿先保存再完成。

相关护理/评分接口局部使用JSONResponse，保留明确评估时间的小数秒，同时保留原业务错误HTTP状态。新迁移`20261020_ai_nursing_sources`接`20261020_ai_image_assets`：护理五项及危重意识允许null，增加来源版本与时间字段，并让护理/ICU的`assessed_at`及危重`record_time`在MySQL采用`DATETIME(6)`。迁移不重写旧分值、解释、分项或发生时间。回退前发现未知值或任一非零微秒就拒绝，在任何DDL前停止，避免用假0或截断精度适配旧结构。

### 五类人工分项汇总

`app/clinical_scores.py`采用`manual_components_v2`。它只汇总人工赋值，不从生命体征自动赋分，不推断死亡率、诊断或PACU转出决定。所有规定分项均必填、必须为实际整数；拒绝bool、字符串、小数、NT、未知分项名和任意`*_score`附加项。

| 记录类型 | 本版人工分项契约 | 范围说明 |
| --- | --- | --- |
| GCS | `eye`1–4、`verbal`1–5、`motor`1–6，三项完整 | 未测或NT时不能计算总分，不能当1、0或默认正常 |
| 原1996 SOFA | `resp_score/coag_score/liver_score/cardio_score/neuro_score/renal_score`，六项各0–4 | 明确原版，不称SOFA 2.0，不由总数确认脓毒症或器官状态 |
| APACHE II | `aps_total`0–60、`age_points`仅0/2/3/5/6、`chronic_health_points`仅0/2/5 | APS为外部人工小计，未自动核实12项生理输入、年龄条件、慢性健康条件或首24小时窗口 |
| 原1970 Aldrete | `activity_score/respiration_score/circulation_score/consciousness_score/color_score`，五项各0–2 | 明确保留肤色项，不冒称改良版SpO₂项，不自动认定可转出 |

### 确认原历史

预览逐日列出`observed_count`，但所有`value`均为null，包括原记录数为0的日期。只有超级管理员分别确认整个窗口完整、每个日已结束、原无时区钟点解释，并填写至少20字依据后，服务器才重算预览摘要、核对`expected_digest`，建立不可变来源。声明明确覆盖整个窗口；部分日期需要修订时必须重新建源，旧声明只能撤销、不能编辑或恢复。声明记录核对人、UTC时刻及原依据，不代表外部历史完整性已被独立验证。

日计数来自原始挂号行，不复用可能只在当天重算过的`DailyOperationalMetric`，也不拼接有限条数的小时汇总。原始UUID、原库钟点和科室按固定顺序流式计算SHA，钟点以六位小数序列化但不增加原存储精度，最多200000条窗口内有时间的原行；超限明确拒绝，不将截断清单当完整历史。无时间行无法分日，单列该全院/科室全部无时间行的`unassigned_time_records`（无法按历史日期限定）并明确排除；不将它们摊入某日或当作零。仅状态变化不改变全状态计数目标，替换原行、修改同日钟点、归属或空时间缺口则会使原声明失效。

`AIForecastSeries`保留冻结日序列、内容摘要、原行摘要、范围、时区、完整性依据和撤销记录。迁移`20261020_ai_forecast_series`接护理迁移，新建一张表，不修改原挂号记录；`create_time/revoked_at`在MySQL为`DATETIME(6)`，创建时间与`coverage_attested_at`精确绑定，撤销时间另行保留UTC微秒。

### 实际统计与分母

固定主算法`weekday_mean_4w`对每个待预测星期取最近28个已观察日中同星期的4个原值均值；第8至14天重复该星期的估计，不把前7天预测值当新观测。三种基线为7日季节朴素、7日均值和28日均值，均使用同一组28个完整滚动起点及相同提前天数，不用本次回测自动选择赢家。基线和时间序列回测原则参考[原作者FPP3章节](https://otexts.com/fpp3/toolbox.html)；112日最低历史、四周主算法和以下经验区间为本项目明确固定的工程配方，不是书中验证过的医院模型。

每个起点只用截至起点日（含当日）已观察的历史前缀，7天跨度有196个预测对、34个不同目标日期，14天有392个预测对、41个不同目标日期。回测使用当前确认快照的历史计数，标记`current_snapshot_retrospective`；它不是当时可得资料的as-of回放，重叠目标日期也不是独立样本。结果自所选历史末日次日起算；旧窗口的外推日期可能已过去，不默认从今天起算。

每个提前天数的区间取更早起点中、目标在当前起点日或此前已经观察到的最近28个绝对误差，按从1开始的`ceil((n+1)*0.9)`位次取半径；下界为`max(0,point-radius)`，上界为`point+radius`。配方至少要求20个可用残差。本版完整窗口保证足够历史，返回实际样本数、位次、半径和最后校准目标日。名义90%经验区间不保证未来覆盖率；回测另报实际覆盖数量/预测对分母、不同目标日期数和平均宽度。

结果同时保留MAE、RMSE、WAPE及MASE。WAPE为绝对误差合计除以实际记录数合计，接口保存比率、界面乘100%显示；分母为0时为null。MASE按各历史前缀的7日滞后绝对差均值缩放，完整保留28个起点的滞后对数、绝对差合计和尺度；任一起点尺度为0时整体MASE为null，不挑选非零子集冒充完整评估。[WAPE原作者说明](https://robjhyndman.com/hyndsight/wape.html)也明确其零分母及趋势数据解释限制；本功能同时给出原分母和其他指标，不以单个百分数确认效果。

### 固定计算范围

规则以 [1996年原SOFA论文](https://www.esicm.org/wp-content/uploads/2018/03/esicmworking5-2.pdf) 和 [Sepsis-3原文](https://jamanetwork.com/journals/jama/fullarticle/2492881) 为来源，明确记录本项目采用的原单位连续边界、医生呼吸支持资格判读及每档连续给药至少一小时等本地实施政策。不同原文或开源实现的边界差异保留在政策中，不称为官方纠正，也不混入SOFA-2。肌酐、胆红素的mg/dL与SI分支，以及PaO₂的mmHg和kPa分支分别按明示原生阈值比较，不作近似换算、舍入或跨分支等价承诺。

输出逐轴保留全部候选、精确有理数、有效区间、实际给药流和决定来源。直接 `ug/kg/min` 不再次除体重，泵速和绝对速率保留明确原浓度、有效成分口径和适用体重；不同药物不拼接，同一物理流不重复相加，冲突区段不能当连续有效给药。GCS仅接受实际完整E/V/M和医生可解释性判读，不使用NT=1、AVPU换算或虚构镇静前分数。尿量仅核对原实际完整24小时区间，不外推，RRT不自动计为SOFA-1肾脏4分。LIS负数、定性结果及不支持的原单位保留为明确未知，不归零或当高分；自由原单位仅保留在院内，外发为受控类型及原单位摘要。

界面分别展示观察到的最高分、已知域小计、未知上下界、数值能否确定和协议是否完整。无已计分域时小计为空；数值上下界相等也不自动证明资料覆盖完整。仅六轴及其必要分支、范围与覆盖全部满足时，才提供完整日总分。

变化核实另行冻结当前完整日评估、实际感染原声明及医生当前的急性变化、归因、时间关系。基线可为独立授权的实测早期24小时、明确条件性零基线假设或未知；两项假设未确认时仍保留未知，不能以既往资料缺失默认0。实测基线须同一患者及规则政策，终点不晚于当前起点；原感染onset已知时还须不晚于onset。服务分别完整重算两日后取 `[当前下界−基线上界, 当前上界−基线下界]`，保留负变化；条件假设与实测分数分开显示。原感染声明可能晚于当前日的历史截止，此时明确标记当前回顾性核实，不冒称旧截止已知。SOFA变化、感染声明及人工归因均不自动形成脓毒症或休克诊断、排除、风险概率或治疗医嘱。

## 受审单物资的已记录原量预测（第66项）

第66项本地 `supply` 模式绑定一件当前已发布的 `supply_series_id` 和明确的整数 `horizon_days`（7或14）。先从药品或耗材目录明确一个真实品种，核对原计量单位、全部每日原件和三个参数，再生成预测。药品与耗材页的“核对原量与预测”绑定当前真实品种；工作台可以明确选择品种，不默认首项。当前库存、价格、采购计划和自由问题不参与该固定计算。

## 受审有限采购候选与库存守恒比较（第67项）

第67项本地 `inventory` 模式比较明确列出的完整采购方案。入口只选择一个真实药品或耗材、一件当前已发布的 `inventory_scenario_id`；工作台不默认首项品种或首个场景，药品／耗材业务行固定当前品种。结果可以证明“该已声明有限集合内的最低采购成本及全部并列可行项”，不能证明所有可能采购组合的全局最优，也不创建采购、调拨、处方、报损或库存变更。

先在原计量单位治理中核对独立单位，再在库存原件面板登记以下三类不可变原件。当前药师本人明确签署专业库存观察；超级管理员负责独立技术审核、发布和撤销，不代替药师确认真实物理量。真实0需要显式输入，未知、未确认、不适用与空值保持各自状态。

| 原件 | 明确登记的内容 | 保留的范围 |
| --- | --- | --- |
| 独立库存观察 | 实际物理范围、观察UTC、原物理总量／冻结数量、原批次和有效期、实盘依据、与本模式完整采集旧账的核对 | 目录库存已经可能扣除预留，不能自动当物理库存；旧账采集时刻不是实盘时刻 |
| 未来出库情景 | 明确IANA业务时区、完整日期范围和逐日原数量、单位及适用依据 | 受审未来情景不是潜在真实需求；不自动将第66项预测升级为事实 |
| 完整采购候选 | 不可拆分的全部订单行、明确到货日、原数量、单价、有效期、订单固定费和方案固定费 | 费用、单位和币种未知分别保留；不推断汇率、默认运费或自动拆单 |

药品目录未记录计数单位时，原始NULL继续保留。只有独立明确的一对一旧账计量核实及依据，才能把旧账原量用于受审计量口径，不补写成“盒”“片”或隐式换算。旧账捕获包括该SKU目录、全部实际药品批次及带符号台账、未明确终止的采购条目；已入库和已取消采购不进入该待履约集合。耗材没有真实批次或台账表时明确保留该缺口，不捏造独立收货表。患者、处方和操作者正文不进入公开数学来源。技术采集的 `observed_at` 保持NULL，不能回填一个过去实盘时间；单批次负值、冻结冲突、总量不符和未知有效期不会被总和抵消。

药师若声明已经核对完整旧账，登记时须绑定其实际查看的完整采集摘要；保存仍在相同事务Gate与品种锁内重新比较。即使目录总数未变，只改变批次冻结或效期，旧核对也返回冲突，不把新的旧账自动附到旧签署上。来源发布、撤销、完整捕获与既有库存写入共用Gate，之后按当前用户共享锁和真实品种排他锁核对当前行，避免旧RR快照沿用已撤销角色或已经取消的采购。

完整场景从截止时刻的全部同品种、同范围和同完整日期段候选生成，不先过滤未知单位、失效签署、未知量或未知费用候选。创建人逐项核对全部原成员、独立库存观察与未来数量，明确候选集合是否完整；还须包含真实零订单、明确零固定费的基线方案。超级管理员分别技术审核并发布场景。新增原件、非赢家变动、当前药师资格或原单位变化，都使旧场景不能继续执行；超管可以独立审计自身字节一致的冻结快照。

场景统一声明1至31个未来完整业务日、同一逐日最小可用量、最大总量、共同采购预算、费用单位及固定政策。第一天必须晚于原 `as_of` 所在业务日。约束可以显式选择已知、未知或不适用；已知限制需要原数量／币种／单位和核实状态，不从空值补0。库存观察到情景起点的携带、冻结量及没有未记录变化等前提分别明确，矛盾会保留为未知，不用最新一条记录覆盖冲突历史。

每天按固定顺序处理：移除已过原有效期的批次、接收当日订单、依有效期和稳定批次标识FEFO分配当日出库，最后核对共同约束。`valid_through` 当天仍有效；只有明确不失效的批次才能声明不适用。冻结量不可用于出库，按日模型不保证日内任意时刻可用；移除过期量只发生在情景账，不表示实际已经报损或处置。精确采购成本计入全部订购数量、全部订单固定费与方案固定费，包括未用完或后来过期的订购量，不包含完整持有、残值、缺货惩罚或其他经济成本。

只要一个候选或集合完整性仍未知，就不能证明全集合最优或全体不可行；已核实的可行候选和并列最低项仍可显示，但明确没有全集合证明。只有全部候选、库存、未来情景、成本和共同约束闭合，才给出有限集合内的最低成本或不可行结论。浏览器按同一固定配方重算整份逐日守恒、所有费用、约束、工作量与并列项，隐藏或篡改一项也不能保留原结论。

v14独立任务只发送类型化匿名 `inventory_source` 和完整系统／任务Prompt。真实品种、单位、原记录键和私有依据按独立HMAC投影；原始私有快照、身份映射、完整原文及自由问题留在院内。任务冻结原Prompt摘要及已登记的实际 `inventory:<SHA>` 模型，普通页面核对冻结锚点，超管另核对原Prompt全文与请求服务快照；这些来源证明不代表独立观察到远端服务内部实现或真实运营效果。

执行先返回短排队回执，再按同一任务ID和上下文摘要获取完整状态；只有完整成功结果通过原件与数学核对后才展示正文。失败、取消和未完成状态保留原状态，不填全零结果。模式痕迹、当前品种／场景、账号、权限、配置或页面生命周期变化会清除旧资料并拒绝迟到回复；已声明原生模式的损坏包不能退回普通文本展示。普通历史重核当前来源，超管冻结审计与新任务执行分开；旧运行版本无法重算时明确说明，不用新配方重写旧结论。

三段迁移 `20261021_inventory_gate`、`20261021_inventory_sources`、`20261021_inventory_scenarios` 接在第66项迁移后，仅新增Gate、原件、完整场景和完整结果四表，含8个UTC微秒字段及5个MEDIUMTEXT列。单原payload、完整父绑定、完整快照／投影／原生请求／响应／结果分别执行明确UTF-8字节上限，整体上限8MiB；最多256个候选、4096个期初批次、8192条订单行、31日、2000万工作单位及4096位精确算术。单项上限不承诺任意组合都能处理，超限整件拒绝，不截断或返回部分最优。

独立服务为 `python -m app.ai.inventory_server --host 127.0.0.1 --port 8823`，使用 `requirements-inventory.txt` 与 `Dockerfile.inventory`，不依赖医院数据库或读取项目`.env`。API、worker和服务显式配置同一份至少32字符的独立 `AI_PROVIDER_LOCAL_INVENTORY_API_KEY`，登记真实保存的服务与模型版本。上传、处理和并发槽位均受完整期限限制，慢分块不逐次延长处理期限。

## 完整病案编码证据与本地规则治理（第68项）

第68项“病案编码证据复核”对一件真实病案首页已经记录的编码逐项形成待人工核实意见。它通过配置的Chat或Responses服务读取最小必要投影，不执行官方DRG／DIP分组，不测算支付金额，不新增诊断、操作或编码，也不修改主诊断、分组记录、收费及首页状态。

从病案首页业务行点击“AI编码证据”进入，入口固定该行真实患者、住院与首页。没有业务行绑定时，须先具备实际患者与住院范围，再从该授权住院的首页目录明确选择，不能猜测首页UUID或默认首项。来源登记与读取均重新核对当前账号、患者、住院、首页关系和既有`operations`授权；管理员、主任、医生等账号角色不代表已具编码专业资质。超级管理员的技术审计权限也不替代临床解释或专业编码确认。

### 先捕获并审核完整Case

在“完整病案快照”中明确是否附加一件受审本地前缀规则包，再预览全部成员并登记。Case完整冻结本首页、全部编码绑定、绑定所对应的当前诊断／操作字典、本首页全部已记分组及其关联当前本地规则；可选规则包也按其完整原件绑定。目录和20行分页只影响显示，登记和复核仍覆盖全部成员，不沿用旧入口的100条编码或5条分组截取。超出成员或8MiB预算整件拒绝，不保存部分Case。

捕获是服务器当前完整采集，不支持补造历史时点。原业务日期、无时区时间和空值按原样冻结；旧naive时间不能解释为已经确认的UTC，也不能证明历史当时已具备这些资料。当前字典发行版本和已记分组的完整历史规则依据保持未知，当前规则或当前字典不能回填成历史版本。

超级管理员在“AI管理→病案编码证据与本地规则治理”核对完整Case、内容摘要、成员清单及治理版本，明确填写依据后发布或拒绝；撤销也须按当前版本和依据提交。发布只表示本件资料经过技术治理，不能把文书支持、医学解释、主诊断或编码正确性变成已确认。原件正文不可改写；首页、编码绑定、对应字典、已记分组、关联规则或所附规则包变更后，应重新完整捕获和审核。

“本地前缀规则包”由超级管理员从实际本地规则目录逐件选择、登记和独立审核。`local_prefix_snapshot`明确只是当前本地前缀规则快照；版本文字、已有分组号和技术发布均不代表官方分组器、官方规则发行版本或历史分组依据。

### 选当前原件，再核对模型可见投影

业务入口只选择一件当前已发布且仍可用的`coding_case_id`。选件时再次读取完整普通详情，即使使用者是超级管理员，也不能拿冻结审计件当执行来源。患者、住院和首页必须与本次入口一致；失效、跨范围、摘要不符或完整成员无法核对时不允许预览和创建任务。

院内完整Case保留原首页、真实身份、私有备注及独立映射秘密。模型只收到已核对的`coding_source`、其投影SHA和本次问题，以及实际系统／任务Prompt；完整私有Case、真实患者／住院／首页绑定、操作者资料和映射秘密不进入模型请求。本次问题同样会发送，应只填写本次复核所需内容。

模型文书限定为入院诊断、出院诊断、其他诊断、手术摘要和并发症五个原字段的最小化显示投影；未记录字段保持缺项，不补空白事实。编码绑定、对应当前字典、已记分组、关联规则和结构检查独立展示，未知类型、停用字典、名称变化、重复编码及主诊断标记冲突继续保留。身份令牌按每件Case独立HMAC产生，已知直接标识与常见联系方式模式在明确显示文本内最小化；这种声明式最小化不保证匿名，仍须遵守患者资料与服务授权要求。

### 引文与逐项意见怎样阅读

成功草稿须对每一条原编码绑定恰好返回一项意见，不漏项、不重复，也不能新增未绑定编码。四种`model_assessment`均是模型主张：

| 主张 | 阅读方式 |
| --- | --- |
| `support_claim` | 模型声称投影文字支持，仍待人工核实医学解释及编码适用性 |
| `conflict_claim` | 模型声称投影文字存在冲突，须回查具体文字和临床情境 |

原文登记上限为4MiB，完整JSON请求上限为8MiB。此容量不等于模型任务容量：任务完整请求、证据、元数据和完整终态记录分别受既有Run TEXT的65535个UTF-8字节约束。Prompt、完整原文、输出及保存候选引用都占用相应容量；单项允许的最大值不承诺任意组合都能保存。超限整件拒绝，不截断原文、不用摘要替代原件，也不返回部分已接收结果。

文字模型只可配置为Chat Completions或Responses，并须获准处理原件中的资料。固定系统Prompt将原文视为不可执行数据；原文中的命令、地址、工具请求和权限声明没有指令效力。独立、可版本化的第71项任务Prompt与实际模型配置、验证状态一同冻结，管理台和默认Prompt导出均显示该独立系统契约。Responses请求显式关闭服务端存储；实际服务的数据处理仍以所配置服务及授权为准。

模型回复只能包含0至64条区间。每条恰有拟题、受控条款类型、`start`、`end`与`quote`。位置采用Unicode码点零起始半开区间`[start,end)`，不是UTF-16位置；引文必须逐字保留BOM、CRLF、组合字符、emoji、标点和原文中的时间字面量。服务器和浏览器都核对完整原件、Prompt、来源摘要、区间与引文。拟题和类型仍是未审核模型意见；逐字一致不证明临床含义、完整覆盖、证据等级或治疗适用性。空集合也不证明全文没有条款。

任务通过短排队回执返回原任务ID，随后读取同一任务的完整原件、SQL锚点与冻结溯源。三个实际保留的原JSON字符串按原UTF-8字节核对，避免把Python的`0.0`重编码为JavaScript的`0`而改变摘要。主应用中的原文治理接口使用保留字节的JSON响应，不经过旧通用接口的微秒清理。

每次终态保存都核对实际Run字段与本次具体审计主键，完整终态记录保存实际用量回执引用及已经明确保存的候选引用。未知输入、输出Token分别保留为`null`，不以旧整数列中的占位零冒充实际用量。排队任务在任何模型调用前取消，记录实际`0/0`与`model_call_attempted=false`；已领取但尚未调用的任务由worker确认零调用后收尾；已经发出的请求取消接收后等待实际用量。缺失一侧用量仍显示未知，取消不接收模型草稿。

候选保存采用当前原件及Run锁、具体终态审计引用和具体候选审计引用，重复保存同一序号返回冲突，不自动重试。完整记录超限或实际SQL写入、审计、来源、权限发生变化时，候选与本次引用一起回滚。保存为草稿不会把拟题或逐字引文提升为已经审核的临床知识。

知识正文仍受既有TEXT的65535个UTF-8字节上限约束。原件、候选和发布记录保留UTC微秒；旧知识表按原有秒精度保存，发布记录另外明确保留`knowledge_recorded_at`及其秒存储依据，不伪造相同精度。撤销原件或候选后，对应知识不再具有当前来源资格；普通知识审核接口不能绕过原文证据链重新发布或修改其审核状态。

超级管理员可在管理页登记、审核、撤销原件与候选，发布知识，管理模型、启用条件、Prompt版本和运行反馈，并在执行溯源中按原件ID筛选任务。冻结历史可以保留已撤销原件的原始签署与当次结果，但页面明确显示当前撤销状态，审计模式不能保存候选或恢复执行资格。退出、切换会话或角色、改变原件或配置及页面失活会清除当前选择与结果；关闭结果会清除该任务详情及冻结溯源，原件选择另可明确清除。迟到的HTTP或摘要计算不能恢复已清除资料。

新增迁移`20261021_document_evidence`接在编码证据迁移后，创建原件、候选与知识发布三表；`20261021_doc_extraction_runs`再新增不可变Run锚点，绑定实际Run、原件、发起用户与八个SHA摘要。既有Run及知识表的TEXT类型、旧业务行和原有临床写入方式保持原有存储契约。模型效果、原文使用授权、隐私与临床适用性须依据实际服务及逐件审核记录确认。

## 完整住院账目与执行核对（第69项）

从“住院收费记录”选择实际住院后使用“AI 收费核对”。系统明确绑定当前患者与Admission；门诊收费记录页提供住院入口说明，不再把门诊账单作为新完整住院任务提交，病案首页也不混用首页引用。可以按本次住院查看新版任务历史；查询使用实际持久原件锚点区分旧版账单任务，旧任务仍可通过原有授权历史读取。

先捕获并核对完整来源，再明确审核发布。完整私有快照保留本次住院的全部已记录收费、医嘱及项目、医嘱层级执行和相关给药记录，包含撤销、退款、零、负数、NULL与未知状态，不按前几十行裁剪。根件和成员总数最多8192、完整快照和来源证明最多8MiB；超过整件拒绝。全局来源目录只列元数据，详情与私有原件必须明确读取。

已有收费行缺少逐行项目／执行外键，不能按同名、同金额、相近时间或现价认定关联、重复、漏费、实际执行或金额分摊。币种、数量单位或财务口径未提供时保持未知。Source发布只确认当前完整技术原件，不是财务、收费资格或专业结论审核。

明确选择一件已发布来源，可以填写可选问题、预览，再提交任务。专属固定System和版本化Task Prompt只向模型发送完整公开来源及问题；患者直接标识和原件治理说明留在私有详情。公开字段最小化不构成匿名保证。模型最多提出128条部分待人工核实问题；有依据的问题须引用本件真实成员公开字符串字段的逐字Unicode码点位置和原字节摘要。保留BOM、CRLF、emoji和组合码点，不归一化引文。空问题集合不证明没有差异，也不证明收费正确。

三个原始任务JSON分别遵守既有TEXT的65535 UTF8字节边界并按原字节校验；完整结果另存在8MiB有界Artifact。结果、原租约、六个任务摘要、具体接受审计主键及Run终态在同一事务核对提交。Chat或Responses的实际输入／输出Token可分别未知；排队取消的已知零、在途取消待回执、付费部分回执和中断未知分别展示，不把占位零当实际用量。模型不会补收费、退费、结算或修改任何原业务记录。

超级管理员可在“完整住院账目来源治理”中显式检查、审核、撤销原件，在“能力与启用”管理模型、允许角色、开关和Prompt版本，并在任务历史按原件及实际患者住院筛选、检查冻结溯源和人工反馈。普通使用者须有当前患者运营权限和相同住院来源；Source变化、撤销、当前角色、会话或配置失效会阻止继续接收，普通旧结果也须重核当前资格。超级管理员冻结审计保留原发布签署和原文，但不恢复执行资格。

## 完整评价证据与部分主题核对（第70项）
