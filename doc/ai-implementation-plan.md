# AI 平台实施记录

本项目按已确认的 80 项 AI 功能规划持续实施。所有 AI 配置由超级管理员管理；业务角色按权限使用能力。功能清单和默认 Prompt 以 `fastapi_be/app/ai/catalog.py` 为机器可读来源。

## 交付批次

| 批次 | 内容 | 验收条件 |
| --- | --- | --- |
| 1 | 80 项能力目录、独立 Prompt、持久化配置、迁移 | 编号与规划一致，Prompt 有任务专属要求和输出契约 |
| 2 | 超级管理员能力、模型、知识和 Prompt 管理 | 普通管理员及其他角色无法修改配置，密钥不通过查询接口返回 |
| 3 | 患者上下文、知识检索、模型调用、建议和反馈 | 校验患者访问范围，引用可核查，模型异常显式失败 |
| 4 | 管理台、业务工作台和共享 AI 面板 | 所有功能可查状态，配置与执行形成端到端流程 |
| 5 | 临床数据标准化、首批 CDSS、文书、检验、导诊 | 数据缺失可见，草稿需确认，保留原有强制规则 |
| 6 | 其他文本能力、运营分析及专用模型适配 | 逐功能验证，专用数据/适配器未就绪时明确禁止执行 |

## 实现约定

- 分支：`feature/ai-hospital-platform`。
- 提交身份：`Palpitate-xus <palpitate.xus@outlook.com>`，每个可验证的小功能单独提交。
- 继续使用 Vue 3、FastAPI、SQLAlchemy 和 Alembic，保留原业务服务；原音识别可通过可选独立适配进程接入统一网关。
- 超级管理员独立管理开关、授权角色、模型、Prompt 版本、知识发布、验证状态和执行审计。
- 区分“已开发”“已配置”“已验证”“已启用”。登记到目录不等于模型已具备临床能力。
- 不提供伪造的模型回答或预测结果。缺少密钥、知识、数据或专用模型时返回明确的未就绪原因。
- 共享系统 Prompt 固定事实、引用、数据边界及人工复核要求；可版本化的任务 Prompt 写明每项功能的输入、处理目标和输出。
- 模型只产生建议和草稿。处方、医嘱、签名、收费、预约等变更继续经过现有业务接口的权限及状态校验。
- 患者资料按本次就诊与时间组织；既往诊断、停药、未知结果和未审核结果保留各自状态。
- 调用外部模型前最小化患者直接标识，保留数据来源；任务记录按现有权限控制。
- 禁忌、剂量、量表和危急值计算交给审核后的确定性工具。预测和原始影像/心电/病理依赖专用适配器及验证。

## 验证

每批运行与变更相关的 pytest、权限回归和迁移测试；前端变化执行生产构建、体积检查及相应 Playwright 场景。路由变化更新自动生成的 RBAC 矩阵。真实临床启用前完成历史回放、静默评估和限定范围试点，并记录知识、Prompt、模型与数据版本。
