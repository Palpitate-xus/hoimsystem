# AI 平台实施记录

本项目按已确认的 80 项 AI 功能规划持续实施。所有 AI 配置由超级管理员管理；业务角色按权限使用能力。功能清单和默认 Prompt 以 `fastapi_be/app/ai/catalog.py` 为机器可读来源。

## 交付批次

| 批次 | 内容 | 验收条件 |
| --- | --- | --- |
| 1 | 80 项能力目录、独立 Prompt、持久化配置、迁移 | 编号与规划一致，Prompt 有任务专属要求和输出契约 |
| 2 | 超级管理员能力、模型、知识和 Prompt 管理 | 普通管理员及其他角色无法修改配置，密钥不通过查询接口返回 |
| 3 | 患者上下文、知识检索、模型调用、建议和反馈 | 校验患者访问范围，引用可核查，模型异常显式失败 |
| 4 | 管理台、业务工作台和共享 AI 面板 | 所有功能可查状态，配置与执行形成端到端流程 |
| 5 | 临床数据标准化、首批 CDSS、文书、检验、导诊 | 数据缺失可见，草稿需确认，保留原有强制规则 |
| 6 | 其他文本能力、运营分析及专用模型适配 | 逐功能验证，专用数据/适配器未就绪时明确禁止执行 |

## 实现约定

- 分支：`feature/ai-hospital-platform`。
- 提交身份：`Palpitate-xus <palpitate.xus@outlook.com>`，每个可验证的小功能单独提交。
- 继续使用 Vue 3、FastAPI、SQLAlchemy 和 Alembic，不额外拆分微服务。
- 超级管理员独立管理开关、授权角色、模型、Prompt 版本、知识发布、验证状态和执行审计。
- 区分“已开发”“已配置”“已验证”“已启用”。登记到目录不等于模型已具备临床能力。
- 不提供伪造的模型回答或预测结果。缺少密钥、知识、数据或专用模型时返回明确的未就绪原因。
- 共享系统 Prompt 固定事实、引用、数据边界及人工复核要求；可版本化的任务 Prompt 写明每项功能的输入、处理目标和输出。
- 模型只产生建议和草稿。处方、医嘱、签名、收费、预约等变更继续经过现有业务接口的权限及状态校验。
- 患者资料按本次就诊与时间组织；既往诊断、停药、未知结果和未审核结果保留各自状态。
- 调用外部模型前最小化患者直接标识，保留数据来源；任务记录按现有权限控制。
- 禁忌、剂量、量表和危急值计算交给审核后的确定性工具。预测和原始影像/心电/病理依赖专用适配器及验证。

## 验证

每批运行与变更相关的 pytest、权限回归和迁移测试；前端变化执行生产构建、体积检查及相应 Playwright 场景。路由变化更新自动生成的 RBAC 矩阵。真实临床启用前完成历史回放、静默评估和限定范围试点，并记录知识、Prompt、模型与数据版本。

- 已建立长期 goal、开发分支和仓库级 Git 身份。
- 已核查现有规则审方、临床上下文、处方明细及测试约定。
- 已完成目录、独立 Prompt、持久化配置、模型网关、知识检索、诊疗授权、任务 worker、管理台与共享业务工作台。
- 门诊病历、处方、药房、导诊、检验、住院病历、手术、首页/ICD、门诊与住院费用、院内导航、预约、运营报表、病区床位及库存预警页面已接入相应共享 AI 入口。
- 已增加精确处方用法、带单位和采样时间的检验指标、独立医生诊断复核、同条件检验趋势、危急值状态、住院医嘱/执行/护理/给药/出院/随访来源；保留原业务状态和患者范围。
- 已移除旧剂量频次猜测，明确规则单位和无法完整评估的原因；药房审核、发药与 AI 共用已保存用法及当前患者条件。
- 任务在模型调用前后核对患者和工具资料，拒绝过期任务及资料变化后的旧结果。
- 超级管理员已可按配置缺口筛选全部能力，查看全院任务与反馈，并追查每次调用时的 Prompt、请求模型、验证和资料快照。
- 已接入明确手术申请/排台/用药引用、有效手术团队关系和原统计时窗口径；多条排台不猜测配对，计划用药不当作已执行。
- 已接入首页及绑定编码、当前有效 ICD 字典文字候选、已记录 DRG 分组和当前关联规则；不补造历史规则版本、诊断或自动绑定编码。
- 已接入住院费用与执行汇总核对、门诊收费与支付票据状态核对；排除跨患者关联和其他就诊，保留退费与未知值，不自动补费或改账。
- 已接入真实院内路线、启用问答、周期共享号源和已审批停诊排除；相应 Prompt 已增加数据边界。
- 收费员仅能被配置使用收费核对，并需超级管理员的限时患者授权；临床历史不随财务任务加载。
- 资料预览使用与执行一致的结构化来源参数；历史任务按患者/就诊筛选，迟到的回执、预览和刷新不会覆盖新选择。
- 已接入分科室的原始日/小时记录汇总、全院已有日统计、当前病区与床位状态；缺失日期、未知时间及配置与实际记录差异均保留。
- 已接入当前周期排班与未来计划区间的停诊/加号申请，明确职称、时段编码与真实资质工时的差别；资质、可用性和工时上下限仍待补充。
- 已接入明确药品/耗材的目录库存、批次、带符号台账、追溯和采购记录；不把追溯当完整消耗，不以计划数量代实收，不推测未知计数单位。
- 药师仅被允许配置库存相关医院级能力，科室范围未取得库存归属时不读取全院库存；不获得全院经营和财务数据访问权。
- 已增加医院级资料预览、原始结果展示和读取时刻，预览不创建推理；生成前后检查业务资料变化，历史结果重新核对原科室/全院范围。
- 已接入计划区间手术申请与排台、历史完成起止，以及完整原时间区间的资源交叠线索；核实患者/住院关联，按实际科室隔离，缺人员资质、设备可用性和时长估计时不声称优化已可行。
- 已接入可核实就诊关联的评价评分与日分布；不读取未审核脱敏原文，不把评分说成总体满意率或编造投诉主题。
- 已接入明确所选的患者关联事件及RCA，不加载无关病史；拒绝事件无外键时的人为就诊绑定，区分上报、处理、已保存分析和未记录的独立核验状态。
- 手术页、运营评价和患者关联事件行已有相应入口；原资料与冻结结果可独立核查，事件行固定患者与事件标识。
- 相应 Prompt 已按真实口径补充限制，当前目录版本为 `2026.10.10`；引用同时保留范围、日期和原记录。
- 全量后端回归：1,299 通过、3 跳过（2026-10-20，98.45 秒）；模型接口均使用隔离测试，没有调用真实计费服务。默认Prompt的来源字段名称及目录版本另由导出检查和18项相关回归覆盖。
- 管理台、工作台、门诊、检验、诊断复核、围术期、编码、收费、导航预约、运营库存及手术/评分/事件来源共 25 项浏览器测试通过；前端构建、体积检查和 594 个接口的 RBAC 矩阵检查通过。
- 80 项清单与完整默认 Prompt 已可从代码导出并检查漂移，见 `ai-capabilities.md` 和 `ai-prompts.json`。
- 后续继续补齐临床结构化数据与各业务数据连接；专用模型、真实知识和临床验证按功能记录状态，不把目录登记标记为临床已完成。
