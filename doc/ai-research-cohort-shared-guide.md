# 科研队列专用任务与共享运行链

本阶段将第74项接入共享任务目录和 worker。功能默认关闭，须由超级管理员明确配置 Provider、Task Prompt 版本、允许角色及验证状态。工程合成数据与隔离模型回执只验证实现；它们不代表真实研究授权、伦理审查或临床验证。

使用者先选取真实项目中的完整受审 Case。任务只接受 `research_cohort_case_id` 与可选原问题；不能用患者、就诊或科室引用替代项目授权，不能让模型修改既定纳排 AST、生成 SQL、扩大队列、自动入组或导出。服务端确定的 true/false/unknown 及有限集合统计独立于模型评论。

功能角色固定为超级管理员、管理员和科主任；普通执行者另须符合当前配置允许角色。超级管理员可管理配置和 Prompt；这种技术身份不替代当前 ProjectACL、逐患者研究授权、明确用途及外发许可。每次模型请求和结果接受都重新核对这些条件。当前有效的本地 Case 不等于已许可外发模型。

共享创建返回短任务元数据，完整 Source、Scope、Task 原始文本和 Result 通过四个独立接口读取。每件分件保留原始 UTF-8 SHA 与大小边界，不把多份大件合成一个必然可容纳的响应。读取任一临床分件前都重新核对当前项目和逐患者权限；撤回授权后，超级管理员也不能借 Trace 或冻结分件恢复临床引文。安全技术目录可保留状态、实际付费用量和 opaque SHA。

共享 worker 保留专用 `ResearchClaim` 的原具体 claim Audit 主键。领取、dispatch 预约、实际 usage、结果接受各有真实独立回执；错误、缺失或 bool 主键不能触发调用或改变首个 worker。重复交付不会重放模型。SQL 事务在模型等待前全部释放，完整结果与原租约、Source、Prompt、Provider 及具体接受回执在同事务读回。

真正排队取消记录已知未调用的零用量；在途停止保留待确认状态，再保存实际回执。服务端未知的 input/output token 保持 null。进程在 dispatch 预约后中断只保留未知状态，不重放付费请求。技术损坏的任务不会降入通用推理；已知技术状态不可能领取的科研队列行保留原 Artifact 与原用量，不阻挡后续合法工作。

本阶段定向证据、实际私有 MySQL 增量范围和失败谱系列于独立 verification。此前 Source 与独立 Task 阶段文档保留原阶段结论。完整后端与全浏览器验收、生产构建预算以及最终合入状态由后续全域报告说明，不能把本阶段的重复定向测试相加为全量通过数。
