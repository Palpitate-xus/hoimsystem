# 第 74 项：有限科研患者集合来源层

本文说明当前独立分支的来源登记、权限核验和病例原件；它不表示科研运行链、模型执行、自动导出或第 75/76 项已经接通。新路由尚未接入生产 `app.main`；自动化测试显式挂入真实应用并使用 JWT、隔离 SQLite 或私有 MySQL。

## 先登记用途，再逐患者记录授权

StudyScope 必须明确项目标识、目的、1..256 个真实患者 ID、拟加入的实际用户、所需记录族、1..366 个旧记录日历日、有效期和使用用途。患者和用户集合必须排序且不重复，医院或科室名称不会自动扩大集合。

用途分为 `cohort_criteria_review`、`deidentification_review`、`research_variable_extraction`。第 75/76 项即使复用这一权限基础，也须明确声明对应用途并重新核验；登记第 74 项不自动授权另外两项。

项目 ACL 指向真实用户，区分 `read_only` 与 `read_capture`。每个患者还必须有单独的研究授权原件；原件保留 `permission_recorded`、`waiver_recorded`、`unknown`、`withdrawn`、`denied`，不把未知或撤回改成正向许可。每份授权绑定原 StudyScope 的 ID、完整内容 SHA 和治理 SHA，不能在提交时偷偷换成后来版本。

项目和逐患者授权的人工核查，与超级管理员的技术发布分开。人工核查必须由另一真实用户对明确原件签署，保存实际审核者、服务器时钟和依据。`recorded_reviewed` 只表示记录了人工核查声明，不自动证明伦理审批、同意的法律效力、研究者资质或隐私处理合格。超级管理员发布一份未知授权，不会使它变成有效研究许可。

`current_care_or_grant` 仅是患者访问依据之一，不能替代项目用途和研究授权。普通临床管理员的全院访问旁路不用于科研授权。多份同时有效的授权、尚未处置的新授权原件或缺失的人工核查，均不会按“最新”或有利记录挑出一个赢家。

## 本地捕获与模型处理分别授权

本地完整捕获、临床正文读取需要当前项目 ACL 和每一名声明患者的当前明确研究授权，超级管理员也遵守此规则。先核完全部患者，再读取第一个临床正文字段；不会先返回已授权部分而省略其他患者。

`external_model_use` 是另一项明确声明。未知或不允许时，本地用途允许的捕获仍可进行，但模型处理预检拒绝；即使是超级管理员也不能靠技术角色绕过。当前来源层没有模型调用或导出接口；允许模型处理的声明也不等于允许自动导出。

超级管理员可以管理项目、授权及技术治理。患者授权撤回或项目 ACL 失效后，病例的 `snapshot`、`public_source`、`local_resolution` 均清空；技术冻结审计可以在服务内部检查原件完整性，但只返回安全技术 manifest 和 opaque SHA，不恢复临床正文或引文。未来若需档案保留访问，必须另建明确授权，不能默认从超级管理员身份推出。

## 完整捕获范围

当前支持五个明确记录族：患者性别/生日字段、挂号、住院、门诊病历、结构化住院病历。每族的精确列集由 `FAMILY_COLUMNS` 声明；这不是患者全部医疗资料。姓名、证件号、电话、地址及未声明的数据族不因这个功能自动纳入。

记录按原患者 FK 和明确日历窗口收集，主时钟缺失的相关成员保留为未知，不按当前日期补齐。旧 naive 时间只保留原日历字面和“时区未知”的依据，不冒充 UTC，也不证明某条记录在历史某时已可得。父就诊或住院关联缺失、患者不一致时保留技术证据，不读取外域父件的临床正文。

所有相关 ACL/授权版本和全部支持成员进入完整摘要。新成员、原文字段修改、非赢家授权新增或撤销都会改变完整集合摘要。以 PK keyset 批读技术 ID，再逐件读取原始字段；相关根总量超过 8192，或完整捕获/病例/公开来源各自超过 8MiB，整体拒绝，不截断后宣称完整。病例原件和公开投影分别受各自容量约束，复合 HTTP 回执不能被误称为单件 8MiB。

## 有限、确定的三值谓词

入排描述是闭合 AST：`all`、`any`、`not`，以及受支持字段上的原记录整数相等、日历日期比较、逐字文本包含；最多 64 个节点、8 层。它不能执行 SQL、访问未授权字段、扩大患者集合或让模型自行决定筛选条件。

每名声明患者都保留结果：`true`、`false`、`unknown`。缺少记录、空字段、不明日期或父关联矛盾保持未知；空的 `every_record` 不自动算真。文本不包含只描述该原字符串，不证明疾病不存在。任何结果都不是临床入组资格认定、效果结论、因果推断或全院队列统计。

原始文本不做空白、BOM、CRLF 或 Unicode 归一化。仅命中谓词时公开所匹配的逐字引文及码点起止；未知分支和未命中的原字段不公开整段正文。姓名等直接标识也可能出现在人工声明的匹配文字中，因此 HMAC 身份映射和最小化引文不等于匿名，更不意味着自动完成第 75 项。

## 病例治理与读取

先预览完整来源并取得 `expected_collection_digest`，再创建病例。服务重新捕获并逐项比对；截止提交前新增、撤销或更改原件时返回冲突，不悄悄采用新数据。病例记录创建依据、全部权限原件、完整成员、固定算法 SHA、随机私有身份密钥和确定判定。

每份病例使用独立随机密钥，以 HMAC 映射患者、记录和字段/原件摘要。真实患者、就诊、用户 ID 及原授权正文不进入公开来源；私有密钥仅留在院内完整病例中。公开来源同时带完整公开 manifest 的 canonical SHA，统计始终基于全部声明患者，不删除未知或不利结果。

技术治理为 draft → published/rejected → revoked，或 draft → revoked，使用明确 revision CAS。发布后公开投影冻结，撤销仍核原 publication 锚；普通读取须原来源和研究授权仍当前。目录只返回技术元数据，不读取病例的大 `snapshot_json`/`projection_json`。每次写入有具体审计事件主键，并在同一事务回读原件、当前角色、授权和审计回执；任一改变则回滚。

该来源层不写诊断、编码、分组、医疗费用或科研业务结果，不复用旧全表/截断 ZIP 导出接口。
