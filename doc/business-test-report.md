## 三、审计发现与修复

以下问题在本轮及前序安全迭代中发现并修复（均已提交，含回归测试）：

### 3.1 业务逻辑类

| # | 问题 | 严重度 | 修复 |
|---|------|--------|------|
| 1 | 自助报到仅凭身份证号可枚举他人预约并代报到 | 高 | 双因子（+手机号后4位） |
| 2 | 检验/检查/体检结果跨患者可读 | 高 | patient 角色强制本人过滤 |
| 3 | 麻醉记录/医嘱执行/护理巡视任意登录用户可读 | 高 | 角色组限制 |
| 4 | 患者角色可审批手术申请 | 高 | 审批限临床角色 |
| 5 | 任意账号可创建分诊记录注入临床数据 | 中 | 限导诊/护理 |
| 6 | 导入患者默认口令 123456 | 中 | 随机初始口令 |
| 7 | 家庭成员绑定可劫持已注册患者档案 | 高 | permission=allow 禁止绑定 |
| 8 | 分页无上限可 page_size=-1 全表拖库 | 高 | 收敛 1..100 |

### 3.2 资金与并发类

| # | 问题 | 修复 |
|---|------|------|
| 9 | 退费并发双退 | 条件 UPDATE + rowcount 校验 |
| 10 | 库存并发双扣/负库存 | 条件扣减 WHERE stock>=n |
| 11 | 号源并发超卖 | 条件 UPDATE WHERE number>0 |
| 12 | 重复发药/重复审计 | 状态条件并入 UPDATE |
| 13 | 退药超退 | 数量条件并入 UPDATE |

### 3.3 系统与数据类

| # | 问题 | 修复 |
|---|------|------|
| 14 | logout 不吊销 token | token_invalid_before 服务端吊销 |
| 15 | 登录锁定进程内存态（重启清零） | 数据库持久化 |
| 16 | 多 worker RSA 密钥不一致致登录随机失败 | 密钥共享机制 |
| 17 | 审计日志与请求会话竞态丢失 | BackgroundTask 写入 |
| 18 | 上传仅信任 Content-Type | 扩展名+魔数双校验 |
| 19 | 导出公式注入（=WEBSERVICE 等） | 6 字符清洗 |
| 20 | viewer_url 可注入 javascript: | https 白名单 |
| 21 | Alembic 迁移双头分叉 | merge revision 归一 |

（完整 31 项修复清单见 `doc/security-launch-checklist.md` 第一节）

## 四、验证确认无问题的业务逻辑

以下经审计确认为正确实现（摘要）：

| 域 | 确认点 |
|----|--------|
| 挂号 | 号源原子扣减/回加对称；退号状态校验；重复挂号拦截 |
| 收费 | 缴费/退费条件更新幂等；日结口径（paid/refund/pending 分列）；金额 Decimal |
| 处方 | 抗菌药三级审批四要素匹配（患者+申请人+药品+未绑定）；过敏史词边界匹配；库存原子扣减 |
| 药房 | 审方→发药→护士核对三段状态机；过期批次禁止发药；退药数量守恒 |
| 医嘱 | 新开→审核→执行→停止/撤销状态机；出院自动停止在院医嘱；执行记录防双护士抢占 |
| 出院 | 未结费用自动结算；床位释放；医嘱联动停止；出院小结幂等创建 |
| 手术 | 申请→审批→排台→术后闭环；取消联动排台取消 |
| 检验 | 样本接收→录入→审核次序强制；危急值四步闭环（通知→确认→处理）幂等且限开单医生 |
| 影像 | PACS 回调 external_order_id 幂等；报告审核驳回可改 |
| 急诊 | 四级分诊；绿色通道唯一进行中申请；审批后先诊疗后付费闭环 |
| 预交金 | 充值/扣减/退款条件更新；balance_after 全程留痕 |
| 病案 | 首页质控退回修改闭环；归档后只读 |
| 审计 | 登录尝试记录（密码不落日志）；敏感操作留痕 |

## 六、结论与建议

**结论**：系统业务逻辑实现完整，核心资金/库存/状态流转均采用并发安全写法；本轮审计发现的所有问题已修复并有回归测试保护，可进入生产上线流程（前置：完成 security-launch-checklist 人工阻断项）。

**后续建议**：

1. 集成回调升级 HMAC 请求签名（防重放），需与 LIS/PACS 厂商协商
2. JWT 有效期 24h 收紧至 2-4h（吊销机制已上线，短期化体验损失小）
3. report.py 报表改 SQL 聚合（当前部分全表加载，数据量大后需优化）
4. 密码策略升级 8 位+复杂度
