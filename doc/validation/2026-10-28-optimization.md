## 依赖与容器审计

Python 3.12.13 升至 3.12.16，pip 固定为 26.2.2；规则与预测服务的 pydantic-settings 从 2.12.0 升至 2.16.2。Vue、Element Plus、Axios、路由与构建依赖同步升级，18 份 Python 哈希锁文件及 npm 均无已知依赖告警，审计没有跳过未识别的 CPU wheel：PyTorch 公共版本公告与实际 `+cpu` 安装版本的对应关系保存在摘要中。

本轮修复依据包括 [pip 安全公告](https://github.com/advisories/GHSA-qwm4-qh6w-59xr)、[pydantic-settings 安全公告](https://github.com/pydantic/pydantic-settings/security/advisories/GHSA-4xgf-cpjx-pc3j) 和 [NGINX 官方安全公告](https://nginx.org/en/security_advisories.html)。npm 初始审计也是零告警，本轮没有将其描述为原先存在 npm 漏洞。

初次容器扫描发现发行版 FFmpeg 带入的媒体、图像和设备库告警。API 与语音容器现从验签的 FFmpeg 9.0.2 构建工具，去掉网络协议与无关外部库，并实际解码 WAV、MP3、M4A、Ogg、Oga、WebM。NGINX 1.30.6 Alpine 进一步更新 Brotli、curl 等系统包。FFmpeg 网络协议漏洞的原始信息见 [Debian CVE-2026-75143](https://security-tracker.debian.org/tracker/CVE-2026-75143)。

## 性能

比较和持续压测使用独立 PostgreSQL 数据库，各限制 API 4 CPU / 4 GiB、数据库 4 CPU / 4 GiB，API 为 4 个 Gunicorn worker。数据包括 10 万患者，以及各 50 万条处方、费用、病历；持续测试另初始化 50 万条审计日志与 20 名医生排班。

| 轮次 | 用户 | 测量 | 请求 | 失败 | RPS | P95 | P99 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 原 SQL 短测 | 100 | 60 秒 | 5,364 | 0 | 89.4 | 1,500 ms | 3,100 ms |
| 合并计数中间方案 | 100 | 60 秒 | 5,197 | 0 | 86.6 | 1,600 ms | 4,400 ms |
| 覆盖索引与批量查询 | 100 | 60 秒 | 6,634 | 0 | 110.6 | 1,200 ms | 2,200 ms |
| 持续压力 | 100 | 30 分钟 | 164,311 | 6 | 91.18 | 1,500 ms | 6,600 ms |
| 稳定负载复验 | 70 | 10 分钟 | 45,602 | 0 | 75.90 | 1,100 ms | 5,100 ms |

30 分钟轮次的 6 个失败全部为开方时库存写门闩超时触发的 HTTP 503，失败率约 **0.0037%**，严格压测命令返回非零退出码。数据库在该负载下达到 CPU 限额；70 用户补测复用了增长后的历史数据。两轮均未出现负库存、重复有效预约、孤立处方明细或孤立费用；新增处方、费用和明细计数一致。

准备、认证、升压和预热排除在测量窗外；在测量窗内发出的请求完成后才记账，结束时在途未记账数均为零。持续轮次 RPS 包含排空时间，短测沿用原对照工具口径。所有请求均检查 HTTP 与业务码。数据规模、审计日志增长和单轮采样差异限制了比较范围，这些结果不作为生产容量承诺。

API 与数据库 CPU、内存、连接和锁等待采样，SQL 统计、写入增量与每次失败保存于 `.local-preview/performance/`。测试容器在归档后停止，数据卷保留；演示项目继续运行。

## 本地部署

页面与 API 实际发布在 `0.0.0.0:51891` 和 `0.0.0.0:51800`。运行版本接口与 OpenAPI 均返回 2.1.0，数据库为 PostgreSQL 17.11，缓存为 Redis 8.10.3，前端为 NGINX 1.30.6。PostgreSQL 保持原演示数据卷的 17 主版本；默认新部署仍保持 16 主版本，避免自动跨主版本更新。

升级前备份了专用数据库和 Redis，Redis 新镜像在隔离卷上成功加载备份后再部署。三类模拟任务各发生 3 次请求：2 次注入的 503 后成功一次，实际由应用 worker 完成有限重试；临床验证标记保留原状态。

本机浏览器的超级管理员、医生、患者及三类模拟任务通过，无页面异常或服务端错误。局域网接口使用不走代理的 HTTP 请求返回 200；本执行环境的 Chromium 对同一私网 IP 返回 503，因此局域网浏览器访问没有计为通过。本机地址 `http://localhost:51891` 的浏览器流程已经验证。
